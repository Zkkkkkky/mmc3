## 1. 范围界定

本模块是 P0 横切基础设施：不是界面功能，而是支撑全部 M01—M18 字段级验收的黄金对照流水线。范围包括：

- 参考版自动采集器（参数化驱动参考 EXE 做单字段修改并保存）；
- 二进制差分引擎（全字节差分 + 归一化偏移剔除）；
- 黄金档案归档（统一存档目录约定与差分报告格式）；
- G1/G2 覆盖率统计报告。

不做：任何具体字段的实现（归各界面模块）；任何界面复刻（归 M01—M18）；参考版行为语义研究（归主文档第 4/5 章既有基准）。

超集功能口径：本模块本身无参考版对应物（参考版无自动化对照概念），流水线属复刻工程的自有基础设施；其产物（黄金档案）用于判定 1:1，不构成 1:1 偏差判定对象。依 D1 决策，与本模块并存的工程能力（.dcmod、撤销重做等）保留不动。

## 3. 参考版界面与行为规格（采集对象与驱动约束）

黄金对照四步闭环（主文档 3.1，REQ-GOLDEN-001）：

1. **复制**：复制基准 ROM 得 `before.nes`，再复制一份 `after.nes` 供参考 EXE 编辑；
2. **单字段修改**：以自动化（pywinauto，参照 `tools/audit_legacy_modifier_ui.py` 参数化驱动方式）驱动参考 EXE，对目标控件做单一字段修改，点"确定"提交到缓冲，再"文件→保存"落盘；
3. **二进制差分**：`before.nes` 与 `after.nes` 全字节差分，记录所有变化偏移；除已知归一化副作用偏移外，变化集必须能被"该字段的预期偏移"完全解释；
4. **重开验证**：全新进程重新打开 `after.nes`，读取同一控件显示值，必须等于第 2 步请求写入的值。

驱动参考 EXE 的技术约束（探针方法论，`output/verification/legacy-ui-probe/summary.md` §5，复用时必读）：

| # | 约束 | 要点 |
|---|---|---|
| 1 | 通用文件对话框"隐藏创建" | #32770 创建但 WS_VISIBLE=False；须 `enum_top_windows(visible_only=False)` 轮询 + SW_SHOW 强制显示 |
| 2 | CPageControl 页签切换 = 子容器显隐 | TCM_SETCURSEL 无效；枚举 TTabSheet 类子容器并 ShowWindow 目标页（主窗口页签 1 存在已知限制） |
| 3 | 运行时错误弹窗 = 进程退出 | 需 ensure_session 自动重启逻辑 |
| 4 | real_click_at 传主窗口 hwnd | WindowFromPoint 用 GA_ROOT 校验；client 坐标经 ClientToScreen 换算 |
| 5 | 点击前刷新已知窗口集 | snapshot_known 防 wait_new_top 误判旧窗口 |
| 6 | 控件 rect 字段为 left/top/width/height | 非 x/y；B03 菜单树 JSON 为 list 根结构 |

REQ-GOLDEN-002：逐字段执行，禁止"改一批字段看一次差分"的混合用例作为对齐依据；混合用例仅可作回归。

## 4. 数据与写入规格（归一化剔除与档案约定）

**归一化偏移剔除（强制）**：参考版每次保存把 6 个偏移的文本 Token `C9 02` 归一化为 `D8 47`，属副作用而非功能（NEG-8）。差分判定（G2）必须先剔除：

| 偏移 | 副作用 |
|---|---|
| 0x4A101、0x4A102 | C9 02 → D8 47 |
| 0x4AE2A、0x4AE2B | C9 02 → D8 47 |
| 0x79538、0x79539 | C9 02 → D8 47 |

证据：`tools/audit_legacy_global_fields.py` 的 `LEGACY_NORMALIZATION_OFFSETS`（REQ-BEH-EX-001/002）。剔除后任何"预期外偏移漂移"即 G2 失败（REQ-BEH-EX-003）。

**黄金档案目录约定（主文档 13.5）**：`output/build/legacy-diff-audit/` 统一存档；每字段一组 before/after ROM 快照与差分报告（JSON）；命名 `<模块>-<字段>-<用例>.json`（如 `unit-hp-write.json`）；差分报告必须记录四要素：请求值、实际变化偏移集、剔除的归一化偏移、重开验证读取值。该目录是 G1/G2 指标的唯一数据源（REQ-GOLDEN-003）。

**性能预算**：黄金对照单用例（复制→驱动→保存→差分→重开）≤30 s/字段（REQ-NFR-PERF-005，自动化批量执行的工程效率要求）。

**验收指标 G1—G6 与本流水线的职责边界**（主文档第 3 章验收指标表）：

| 指标 | 主文档口径 | 与流水线的关系 |
|---|---|---|
| G1 黄金对照覆盖率 | 已通过黄金对照的字段数 / 参考版全部可编辑字段数 ≥95% | 分子分母均由黄金档案目录自动汇总（第 5 节统计职责） |
| G2 逐字段差分通过率 | 差分变化集可被预期偏移解释的用例比例 =100% | 差分器剔除归一化偏移后判定；撤销/重做路径（REQ-NFR-STAB-004）与性能优化路径（REQ-NFR-PERF-006）同样纳入 G2 判定 |
| G3 禁用解禁数 | 因"未验证"禁用控件数从 ≥15 降为 0 | 流水线每通过一字段即解禁对应控件，逐项联动 |
| G4 动线签核 | 17/17 模块导航动线人工双端执行签核 | 人工签核职责，黄金档案不替代（由各模块第 7 节验收清单承载） |
| G5 运行时验收 | Mesen 实机抽查战斗公式/道具/经验数值 | 黄金档案通过后抽样执行，非自动判定 |
| G6 导出产物像素比对 | 导出机体/头像 BMP 逐像素一致 | 归 M18 采集，本流水线仅提供档案格式约定 |

## 6. 实现注意事项与禁区

1. **禁区：references/ 全程只读**——参考 EXE 与基准 ROM 只在隔离副本上运行（探针先例：exe 于工作目录副本运行、ROM 用 probe.nes 副本、保存对话框截屏即取消）；禁止对 `references/` 任何写入；
2. **禁区：混合用例冒充对齐依据**（REQ-GOLDEN-002）；
3. **禁区：差分不剔归一化即判定**（REQ-NEG-002/REQ-BEH-EX-002）；
4. **禁区：跳过重开验证**——第 4 步是"保存后继续编辑无需重开；重开后显示值必须等于已保存值"的语义（REQ-BEH-002）；
5. 与当前产品代码的衔接点：`tools/audit_legacy_modifier_ui.py`（参数化驱动范本）、`tools/research/legacy_ui_probe.py`（探针库 56KB 可复用）、`src/fc_editor/profiles.py`（指令签名校验，如 double_hit_operand_groups 第三镜像校验思路）；
6. 决策纪律：否定证据（NEG-1~NEG-8）不计入对照基线；判定 1:1 时差分范围仅限参考版存在的功能行为（REQ-NEG-001，依 D1 决策）；
7. 离线驱动不可行结论：参考 EXE 无法离线驱动——配置文件仅为显示名列表与码表，写 ROM 唯一路径是 GUI“确定→文件→保存”（rebuild_exe.py 证实纯 Win32 GUI），采集只能走 pywinauto GUI 自动化；
8. 第三镜像 extra_allowed 决策：双击三参数第三镜像 0x7FF03/0x7FF12/0x7FF1A（来源 `src/fc_editor/profiles.py` double_hit_operand_groups 三镜像）在注册表预填 extra_allowed，verify 复算中以 known-exception 分类（本期 3 例）；
9. 同批提交流程约定：注册表 `tools/golden_pipeline/cases/field_registry.json` 与 `golden/` 档案产物（含 index.json）由 `report_golden_coverage.py archive` 一次性生成，必须同批提交——只提交其一会导致 index/注册表与档案目录的一致性测试失败（档案孤儿检测与快照登记互为镜像校验）；
10. passed 判定口径：golden 用例通过除“无未解释偏移”外还要求必写偏移全部写入（required ⊆ changed，语义对齐 audit_legacy_global_fields 的 target_offsets_changed 检查）；item-prices 价格字段的高位字节（仅进位时变化）归 optional，不计入必写集合（档案 JSON 新增 required_offsets/optional_offsets 字段，schema 向后兼容）。
11. 在线采集命令：从仓库根目录的**交互式 Windows 桌面终端**运行 `.\.venv\Scripts\python.exe tools\report_golden_coverage.py collect --case-config tools\golden_pipeline\cases\M17-hit-threshold-cold-start.json`；项目开发依赖需安装 `pywinauto`。默认只使用 `output/build/legacy-diff-audit/audit.nes` 和同目录隔离参考 EXE。配方按 `module/field/case_id` 建隔离目录，已有目录不覆盖，失败写 `error.json`，成功或判定不通过写 `case.json` 与 `legacy-live-results.json`；随后 archive/stats。配方操作白名单为 menu/window/click_id/set_text/select_index/list_double_click/click_coords，后续 M01—M18 控件若不适配，先扩展驱动和测试，不能以任意脚本片段绕过。
12. 在线 passed 门禁同时要求预期外偏移为空、必写偏移已改变、冷启动重开显示值等于请求值、完整用例（从复制起计时）≤30 秒；`reopen_mode=new_process` 和两个 PID 写入档案。旧 61 例的重开模式继承原审计证据，不因元数据兼容而冒充本次在线冷启动验证。`golden/index.json` 采用 `module/field/case_id` 键，允许一个字段保留边界用例；覆盖率 G1 仍按唯一字段计数。
