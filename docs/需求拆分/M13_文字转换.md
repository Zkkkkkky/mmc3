# M13 文字转换

> 模块编号：M13 ｜ 状态：已实现（未验证） ｜ 优先级：P2 ｜ 依赖：M11 字库编辑（共用字库编码，5.7）、M14 剧情事件（共用文本 Token 码表）｜ 主文档章节：4.11 / 5.7 / 11.12
> 决策依赖：无

## 1. 范围界定

本模块实现参考版"文字转换"窗口（7 控件）的双向转换工具：

- **做**：文字→代码（逐字映射为 ROM 文本 Token 十六进制串）与代码→文字（逆运算）两个转换动作；转换表与字库编码严格一致（REQ-TC-003，5.7）；F-071 未知字/控制码全量对照。
- **不做**：任何 ROM 写入——本窗口为即时工具，无确定/取消按钮、不产生修改、不进入保存模型（REQ-TC-002，6.1 例外条款）；不提供码表编辑（码表维护属字库/研究范畴）。
- **超集口径**：本窗口无直接对应超集项；依 D1 决策（2026-09-14）既有超集能力保留、不构成 1:1 偏差，且不得改变本窗口参考版控件与动线。

本模块为纯工具模块：无数据写入风险、无状态持久化，验收以输出一致性比对为主，是全部模块中验收成本最低的一个；但 F-071 全量对照是 M11/M14 文本编辑正确性的前置基础设施，需优先完成。

## 3. 参考版界面与行为规格

**入口动线**：主窗口菜单项「文字转换&(Z)」，快捷键 Ctrl+Z（B03_完整菜单树.json 实证；菜单结构随 ROM 载入出现，REQ-MW-001）。点击后弹出本窗口。

**窗口**：7 控件（控件树 C04 节）。布局自上而下：输入/输出两行 Edit+Label 与两个转换按钮。

| 控件 | ID | 类型 | 说明 |
|---|---|---|---|
| 文字输入 | 100 | Edit | 待转换文字 |
| 标签 | 110 | Label | 输入区标签 |
| 代码输出 | 130 | Edit | Token 十六进制串 |
| 标签 | 120 | Label | 输出区标签 |
| 文字转代码 | 140 | Button | 文字→Token |
| 代码转文字 | 150 | Button | Token→文字 |

- REQ-TC-001：文字转代码把输入文字逐字映射为 ROM 文本 Token 十六进制串；代码转文字为其逆运算。
- REQ-TC-002：窗口无确定/取消（即时工具，与操作动线规格一致）。
- REQ-TC-003：转换表与字库编码一致（5.7）。

**操作动线**：菜单/快捷键打开窗口 → 在文字输入(100)键入或粘贴文字 → 点文字转代码(140) → 代码输出(130)显示 Token 十六进制串；反向：在代码区键入 Token 串 → 点代码转文字(150) → 文字区显示还原文本。转换即时完成，不弹任何确认。

**行为要点**：

- 两个转换按钮即时生效，无中间确认步骤（REQ-TC-002）；
- 输入/输出区均为 Edit，可选中复制；
- 窗口关闭不产生任何提示（无脏状态概念）；
- 交互细节（转换后是否选中/清空另一侧等）以参考版实测为准，不得臆测。

- controls/controls_summary.md（C04 节控件树）

## 4. 数据与写入规格

- **不写 ROM**：本模块无任何写入路径；输出仅为界面文本，可复制。
- **码表**：转换依据与字库编码一致的 Token 表（5.7）；参考版码表配置文件 `码表.ini` 实测 3328 行，行格式 `地址=Token=字`（首行 `06C010=B800=厮`）——地址与字库页基址（0x6C010，M11）对应、Token 高字节与字库段号（B8，GLYPH_PAGE_LEADS）对应，即"转换表与字库编码一致"的机理实证；该文件为 E4 级参考。当前实现 `src/fc_editor/codecs/legacy_text.py` 的编码表为 E5 现状——两者以参考版实际转换输出对齐（F-071），不一致处以参考版输出为准并回填。
- **文本 Token 双字节**（5.7）：剧情文本八组选择子（$32/$33/$36/$37/$38/$39/$3A/$3B）；`C9 02`/`D8 47` 为"空格/换行"类 Token（见 6.3 归一化——该归一化是参考版保存副作用，本模块转换本身不涉及，但输出比对时须注意参考版 ROM 可能已被历史保存归一化的差异）。
- **未知字/控制码**：码表未覆盖的输入字符与控制 Token 的行为（直通/拒绝/占位）【待 F-071 全量对照确认】——对照完成前不得自行猜测行为。
- **输出格式**：Token 十六进制串的显示格式（大小写、字节间分隔符）与非法输入（非十六进制字符、奇数长度、多余空白）的解析容错【待对照确认】——以参考版 C04 截图与实测为准。
- **状态**：窗口无持久状态；同一输入重复转换结果幂等。

**码表行格式示例**（码表.ini 实测，GBK 编码，共 3328 行）：

| ROM 地址 | Token | 字 |
|---|---|---|
| 06C010 | B800 | 厮 |
| 06C022 | B801 | 渴 |
| 06C034 | B802 | 哭 |
| 06C046 | B803 | 躯 |

## 6. 实现注意事项与禁区

1. **禁区：不写 ROM**——任何路径都不得触发 ROM 缓冲修改或保存按钮状态变化。
2. **码表单一来源**：转换表与 M11 字库、M14 剧情文本共用同一实现（REQ-TC-003）；禁止在本模块私建第二套码表导致三处口径漂移。
3. **未知字行为不得臆测**：F-071 对照完成前，未知字/控制码行为以参考版实测为准；不得按"合理推断"实现（3.4 纪律）。
4. **无确定/取消**：窗口按钮仅 140/150 两个转换动作；不得追加确定/取消或"应用到 ROM"入口（超集功能另置且不改本窗口）。
5. **衔接点**：`src/fc_editor/codecs/legacy_text.py`（文本 Token 编解码）；实现时以此为基础扩展全量对照脚本。
6. **快捷键与菜单入口**：菜单项文本「文字转换&(Z)」与快捷键 Ctrl+Z 按菜单树实证复刻；不得增删改参考版已有菜单项（REQ-NFR-SUPER-001）。
7. **与 M11/M14 的联动验收**：码表修正后，M11 字库预览的字符定位与 M14 剧情对话/胜利文字的往返转换必须同步复验，防止码表变更引入跨模块回归。
8. **回归时机**：F-071 全量对照完成后，本模块纳入 M17 模板区回归纪律（每完成一个模块重跑全量审计）时一并复验输出一致性。
