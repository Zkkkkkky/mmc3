## 1. 范围界定

本模块实现参考版"导出机体"批量导出与"导出头像"两项功能：

- **做**：导出机体菜单动线（数据→导出机体 Ctrl+F，命令 20017）与系统通用保存对话框（REQ-EXP-001）；按五 BMP 协议批量导出全部机体（REQ-EXP-002）；产物与参考版逐像素一致（REQ-EXP-003，G6 验收）；参考版导出头像项按 D2 置灰（F-097）；已有头像两图 BMP 导出作为超集功能迁至“扩展功能”（F-S18）。
- **不做**：按推测协议实现导出头像导出行为（C 选项禁止）；机体组合像素规则未与 B3 样本完成 G6 比对前不宣称对齐；不改动超集 .dcunit 机体包（F-S08，依 D1 保留）。
- **边界**：导出读取的是当前内存 ROM 缓冲中的图形数据（与参考版一致）；全程不写 ROM、不弹确定/取消——与两级提交模型（6.1）无关。
- **超集口径**：当前产品 .dcunit 包导入/导出（F-S08）与头像 BMP 导出（F-S18）均为超集/新协议形态——依 D1 保留、不构成 1:1 偏差；依 D2，头像 BMP 导出改从“扩展功能”进入。参考版机体旧协议导出必须另行实现，不得以 .dcunit 替代宣称完成。

当前产品现状（2026-09-18）：`Ctrl+F` 已接入参考版 001—255 批量五 BMP 路径；完整 B3 全集 1275/1275 个目录路径与 BMP 整文件一致，聚合 SHA-256 均为 `FB2122766C647507D357B62B5799B0856FCAB01F4EC649A889793F63A9FAC102`，且导出前后工作 ROM SHA-256 不变。F-097 的数据菜单项已永久置灰并标注参考版不可触发，增强头像导出已迁至“扩展功能”且不占用 Ctrl+L；`.dcunit` 继续由“机体导入与CHR图像”超集页面提供。自动化与黄金验收已通过，用户签收表仍保持空白。

## 3. 参考版界面与行为规格

**入口动线**（controls/B03_完整菜单树.json 实证）：

- 导出机体：数据菜单「导出机体&(P)」，快捷键 Ctrl+F（命令 20017）。
- 导出头像：数据菜单「导出头像&(L)」，快捷键 Ctrl+L（命令 20018）。

**导出机体操作动线**：数据→导出机体（Ctrl+F）→ 弹出系统通用保存对话框（`#32770`，保存&S/取消）→ 选定根目录 → 参考版批量导出 ID 001—255（不含 000）的全部机体。另据差异矩阵（E4）：机体列表右键入口仅导出当前项、头像入口仅导出当前人物【推断待验证：右键/头像入口在探针轮次未复现，需黄金对照补证】。

**导出头像否定证据 NEG-5**：菜单项触发后无任何窗口创建（探针多轮触发+40/90/300s 轮询不可复现）——参考版该功能不可触发；处理方式见 D2。

**保存对话框**（D11，force-show 方案捕获）：51 控件系统通用 `#32770` 保存对话框（保存&S/取消）——参考版未提供自定义控件，全部为系统对话框控件（文件名编辑框、目录树、保存类型下拉等均为 Windows 系统控件，复刻版直接接系统对话框，无需自绘复刻）。对话框默认文件名/默认目录参数【待黄金对照补证——force-show 捕获的是空参数形态】。

## 4. 数据与写入规格

- **只读导出**：本模块不写 ROM——全部产物为磁盘 BMP 文件；无确定/取消（菜单命令直接触发保存对话框）。
- **BMP 编码参数**（B3 动态样本 E3 级 confirmed）：24-bit BI_RGB、BGR 字节序、正高度 bottom-up 行序；尺寸、文件长度及其余头字段按协议表。编码器字节一致性仍由 G6 运行时比对验收。
- **像素组装规则**：机体战斗图 128x128 复用 8x8/7x9/9x7/10x6 拼图协议（4.5 机体拼图尺寸按钮口径，5.8）；`[机体]`/`[碎片]` 使用固定素材四色，`[效果]` 使用 ROM 游戏色并把碎片黑色像素视为透明。旧版导出与游戏预览存在一个已证实差异：碎片图块起点越出 128×128 画布时整块跳过，不对可见尾部逐像素裁切（槽位 009/010）。`[图标2]` 使用素材四色；`[图标1]` 使用 B3 全集证明的 255 槽位敌我色表。图标前两页为 `$34/$35`，第三页按参考目录阶段路由 `$36/$3A/$3C/$3E/$40`。以上规则已通过 1275/1275 整文件 G6，不再是 candidate。
- **拼图尺寸口径**：8x8（标准）、7x9/9x7（窄高/宽矮变体）、10x6（宽扁变体）四尺寸对应参考版机体编辑的拼图尺寸按钮；导出与 4.5 机体编辑共享同一拼装实现，不得另造第二套口径。
- **头像数据源**：超集 F-S18 从人物头像数据只读导出 32x32 点阵；由于参考版导出不可触发（NEG-5），该超集产物仅做自身格式与确定性回归，不宣称与参考版像素协议对齐。
- **导出头像（D2）**：参考版不可触发（NEG-5）；对齐菜单项按已决口径置灰并标注，Ctrl+L 不触发增强导出；当前产品既有头像 BMP 导出属新协议（F-S18），作为超集功能迁至“扩展功能”。
- **命名细节**（B3 confirmed）：根目录固定 `导出的机体`；目录 ID 为三位十进制补零；目录名使用全角冒号；ID 246—255 的空名称不得裁掉冒号；文件名前缀重复目录中的名称，空名称时直接以 `[` 开头。
- **图标语义**：[图标1]/[图标2]（16x16）为机体图标两种形态；B3 只能确认两者像素产物不同，具体帧/用途仍待参考版运行时验证。[效果]/[机体]/[碎片]（128x128）为战斗图三形态。

## 6. 实现注意事项与禁区

1. **D2 已决策**：“数据→导出头像”项置灰且 Ctrl+L 不触发增强导出；已有头像 BMP 导出迁至“扩展功能”独立入口；不得按推测协议将超集行为冒充为参考版对齐行为。
2. **G6 一票否决**：像素不一致即未完成——不得以"视觉相似"替代逐像素比对；比对工具纳入 P0 流水线。
3. **协议证据纪律**：B3 已确认目录命名、文件名、数量、尺寸和 BMP 头；像素组装与当前编码器输出未通过 G6 前，UI 仍不得宣称“旧版协议已支持”。
4. **超集并存**：.dcunit 机体包导入/导出（F-S08）保留且默认可见（D1）；旧版协议导出为独立菜单动线（Ctrl+F 同一入口接旧协议），不得移除或改名参考版菜单项（REQ-NFR-SUPER-001）。
5. **全角冒号**：目录名 `：` 为全角——编码/文件系统层面逐字复刻（Windows 文件名允许全角冒号，半角冒号非法，注意区分）。
6. **快捷键**：Ctrl+F（导出机体 20017）按菜单树与命令 ID 实证复刻；Ctrl+L 对应的参考导出头像项因 D2 置灰，不分配给超集导出。
7. **衔接点**：`src/dc_modifier/` 既有 .dcunit 导出与头像 BMP 导出（超集/新协议）——旧协议实现为新增路径，不动超集入口；像素组装复用 4.5 机体拼图口径（8x8/7x9/9x7/10x6）。
8. **回归联动**：本模块不写 ROM；完成后与其他模块一样触发 M17 模板区回归重跑。
9. **产物基准库**：参考版导出产物全集存档至 output/build/legacy-diff-audit/（G6 比对基准库）；基准库一旦建立不得覆盖，只追加。
10. **ID 范围口径**：批量导出固定为 ID 001—255（255 项），不得导出 000；即使名称为空也必须创建目录和五图。ROM 内部 0x100 项与导出编号的映射须显式处理，不能把内部索引 0 直接输出为 000。
11. **批量规模**：全量固定 255 项、每项五图落盘，须顺序导出、及时释放句柄（一次性全载入内存的形态禁止）；单个机体导出失败不得中断整批，以失败清单记录收尾【参考版失败行为待实测确认】。
