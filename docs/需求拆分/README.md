## 1. 拆分目的

主文档是 1:1 复刻的唯一需求基准（13 章约 1565 行，面向 G1—G6 整体验收）。为支撑"按模块实现、按模块验收"的节奏，将主文档第 4/5/11 章的模块级内容拆分为 19 份可独立执行的模块文档：

1. 每份模块文档自带功能点清单（逐行继承主文档第 11 章 F 编号）、黄金对照采集清单、用户验收清单；
2. 实现代理按模块文档逐模块实现、逐模块自验；
3. 用户按各模块文档第 7 节"用户验收清单"逐模块验收，结果回写本文档签核总表与主文档第 11 章。

### 4.1 正式开发队列（2026-09-15，用户要求记录）

以下是 P0—P3 分类内的具体执行顺序；M02 按 8.2 的例外提早验证。一个模块涉及不同风险级别时分阶段交付，不因基础部分完成而把整个模块标为“已对齐”。这是计划顺序，不是完成状态；每步先完成实现侧自验，再交用户按模块验收。2026-09-16 用户确认队列前 3 项已签收，按遗留项均记录为“有条件通过”；下一项仍为 M17，M00—M02 的补证不因签收而撤销。

1. **M00 黄金对照流水线**：跑通单字段修改、保存、全字节差分、归一化过滤和全新进程重开；后续新模块的“已对齐”以它为前置。
2. **M01 启动器与主窗口**：核对打开/保存、另存、未保存提示和两级提交。
3. **M02 战场地图**：验证现有地图能力、地形/图块属性与图库 H，作为部署和事件编辑的地图基础。
4. **M17 其他窗口**：回归已对齐的全局参数，签核初始阵容数据源。
5. **M05 → M06 → M07**：依次做机体、人物、武器的字段级黄金对照与编辑。
6. **M08（基础）→ M09（经验/成长）→ M10**：先战斗对话基础编辑，再安全范围内的经验/成长与其他修改1，最后其他修改2的商店/文字数据；等级布局留给 P3 核定。
7. **M03 初始配置**：利用已验证的地图、人物、机体和初始阵容；控件枚举及部署记录黄金差分通过后才开放写入。
8. **M04 商店事件**：利用地图和 M10 商店数据；控件枚举及事件记录保存差分通过后才解除只读。
9. **M11 → M13 → M08（文本搬移）→ M14**：依次做字库、文字转换、战斗对话搬移和剧情事件。
10. **M12 → M18 → M15**：依次做地图动画、机体/头像导出、属性计算器；M18 使用 B3 ZIP 做 G6 像素对照，M15 倍数入口遵守 D6 禁用/验证口径。
11. **M09（等级布局兼容性）→ M16**：最后核定当前 ROM 与旧 3778 字节样本是否同构，再逆向存档两表；未经布局证据不得解禁等级写入。

如证据、依赖或安全约束要求调整顺序，先在本节说明变更原因和新顺序，再实施；不得用跳过验证来宣称模块完成。每次开发结束时的“已做/未做/验证/下一步”见 `docs/开发记录.md`。
