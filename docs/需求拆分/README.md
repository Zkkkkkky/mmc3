## 1. 拆分目的

主文档是 1:1 复刻的唯一需求基准（13 章约 1565 行，面向 G1—G6 整体验收）。为支撑"按模块实现、按模块验收"的节奏，将主文档第 4/5/11 章的模块级内容拆分为 19 份可独立执行的模块文档：

1. 每份模块文档自带功能点清单（逐行继承主文档第 11 章 F 编号）、黄金对照采集清单、用户验收清单；
2. 实现代理按模块文档逐模块实现、逐模块自验；
3. 用户按各模块文档第 7 节"用户验收清单"逐模块验收，结果回写本文档签核总表与主文档第 11 章。

1. 每一优先级内的模块必须按主文档 3.3 节四条件全部达成才可宣称"已对齐"；
2. P0 完成前禁止宣称任何新模块"已对齐"（#19 模板区除外，其黄金对照已存在）；
3. M02 的地形/图块属性黄金对照可随 P1 批次提早启动（8.1 #2 为"基本完成"状态）；M18 的旧版 BMP 黄金样本已于 2026-09-14 到位；
4. D2、D3 已于 2026-09-14 回答；D4—D6 相关模块在决策归档前按保守方案执行，不得放宽。

## 5. 逐模块验收流程

每个模块按五步闭环（主文档 10.2"模块验收流程"）：

1. **黄金对照采集**：按模块文档第 5 节清单逐字段执行四步闭环（复制→单字段修改→差分→重开），结果存档 `output/build/legacy-diff-audit/`；
2. **实现**：实现代理按模块文档第 3/4/6 节规格实现（含禁区遵守）；
3. **代理自验**：实现代理按模块文档第 2 节"验收方式"列自验（L1 控件清单比对、L2 动线、L3 字段黄金对照、G2 差分审计）；
4. **用户验收**：用户按模块文档第 7 节清单逐条执行并填写通过/验收日期；
5. **签核回写**：验收通过后回写主文档第 11 章对应功能点状态、本文档第 6 节签核总表、模块文档第 8 节状态跟踪。

回归纪律（主文档 10.2）：每完成一个模块，将 #19 模板区（其他全局参数，M17）审计脚本全量重跑作为全局回归，防止跨区破坏。

## 7. 模块文档统一模板与状态口径

每份模块文档固定八节：范围界定 / 功能点清单 / 参考版界面与行为规格 / 数据与写入规格 / 黄金对照采集清单 / 实现注意事项与禁区 / 用户验收清单 / 状态跟踪。

状态口径（与主文档第 11 章六分类完全一致，不用图标）：

| 状态 | 定义 |
|---|---|
| 已实现（已对齐） | 通过黄金对照四步闭环验证，附结果存档路径 |
| 已实现（未验证） | 功能可用，但未做参考 EXE 黄金对照差分 |
| 部分实现 | 模块可用，但有字段禁用、能力缺口或覆盖不全 |
| 未实现 | 参考版有，当前产品完全没有对应能力 |
| 外壳/禁用 | 界面有入口/按钮，但禁用或只读（tooltip 注明原因） |
| 超集自有 | 参考版没有，当前产品独有（依 D1 决策保留，不构成 1:1 偏差） |

F 编号纪律：只能从主文档第 11 章对应小表逐行抄录，不得自造；模块含第 11 章未覆盖的功能点时标"新增（无 F 编号）"并注明来源章节。

## 8. 维护纪律

1. 模块文档随实现进展更新第 8 节状态跟踪；功能状态升级（如"未验证→已对齐"）必须同步回写主文档第 11 章；
