## 1. 范围界定

本模块实现参考版“存档编辑器”窗口（13 控件）的四阶段存档编辑能力：

- **已实现**：窗口结构与四阶段动线（打开存档文件→读取存档→编辑两表→写入存档→保存存档文件，REQ-SAVE-001）；存档槽/关卡两下拉；两张 11 列表；严格 8 KiB 结构检查；三槽读取、校验、编辑与校验和重算；活动战场敌方已证实字段读取/写入；时间戳备份与原子落盘；存档写入独立于 ROM 两级提交，但按 2026-09-19 ROM 优先启动决策，GUI 入口在打开 ROM 后提供（REQ-SAVE-006）。
- **证据边界**：常驻队伍和活动敌方数值均有 ROM/实际 SRAM 地址证据。活动 SRAM 不保存逐敌机体 ID或基础金钱，因此这两列只在当前 ROM 关卡部署能匹配时推导并保持只读；未匹配时明确显示“未解析”，不伪造字段。
- **参考动态结论**：同完整性级别自动化已枚举 13 个物理控件、上下表 22 个列角色和 18 个逻辑字段族。仓库保存的 15 份 8 KiB SAV 全部显示“1：没有数据”，下表均为 0 行，并在读取后统一报错误 4；上表 11 列逐列双击无编辑器，强制 EXP 写入也为零差分。因此参考保存字段按运行时不可达排除，不冒充黄金通过。
- **超集口径**：覆盖前唯一时间戳备份和原子替换是 D1 安全增强；不改变参考版的四阶段动线。

当前产品现状：F-088—F-090 均已实现并有自动回归；参考控件范围已封口，产品仍待用户验收，不再是外壳。

## 4. 数据与写入规格

- **存档格式**：固定 8192 字节 SRAM；其他尺寸在“打开”阶段拒绝，不做前缀猜测或截断。
- **活动/备份**：活动块文件偏移 `$1411`、长 `$0437`；备份块 `$1848`、长 `$0437`，备份校验和 `$1C7F`。产品读取活动常驻区和活动战场数组，不擅自镜像整块备份。
- **三槽**：槽 1/2/3 起点 `$1C81/$1D7E/$1E7B`，每槽 `$FB` 字节；校验和 `$1D7C/$1E79/$1F76`，算法为槽内所有 251 字节求和并截为 16 位，小端存放。有效槽必须校验通过、关卡原码为 0—31且至少一名人物有效。
- **槽内字段**：`+00` 关卡；`+29..2A` 金钱；`+2B/+3B/+4B` 起各 16 字节人物/机体/等级；`+5B/+6B/+7B/+8B` 起四项道具附加；`+9B/+AB` HP 附加低/高位；`+BB` 状态；`+CB` 精神附加；`+DB/+EB` EXP 低/高位。
- **上表**：显示有效槽的非空队伍；无数据槽使用活动常驻区作为新槽模板。载入 ROM 时，最终属性 = 机体基础 + 等级成长 + 人物补正 + 存档附加；编辑最终属性时反算附加并拒绝负值/越界。未载入 ROM 时显示原始 ID 和附加值，仍可独立工作。
- **下表**：读取活动块敌方 18 格的人员、等级、机动、强度、防御、速度、当前/最大 HP 分列数组。UI 允许写回人物与六项数值；机体图像字节保留。逐敌机体 ID 和金钱不在 SRAM，只能由当前 ROM 的关卡部署匹配并只读显示，无法匹配时明确留空/未解析。
- **四阶段**：“打开”只选定并检查尺寸；“读取”才载入和解码；“写入”修改内存副本、重算所选槽校验和且磁盘不变；“保存”先建立唯一时间戳 `.bak`，再同目录临时文件 `fsync` 并原子替换。
- **独立会话**：存档修改不进入 ROM 两级提交模型；正常 GUI 启动先载入 ROM，再从“数据”菜单进入存档修改器。ROM 只提供名称/基础属性和关卡部署的可选解析上下文。
- **存档槽摘要**：有效槽显示 `N：第NN关 · X人`，无效/空槽固定 `N：没有数据`；校验失败不会被伪装为可编辑旧数据。
- **关卡下拉联动**：槽内原码 0—31 显示为 01—32；读取所选有效槽时取槽关卡，无数据槽取活动记录。

## 6. 实现注意事项与禁区

1. **严格尺寸**：只接受 8192 字节；不得自动补零、截断或在未知前缀中搜索槽位。
2. **槽校验**：修改槽内任何字段后必须重算对应 16 位累加和；不得更新其他槽或活动/备份整块。
3. **独立会话**：存档 codec 和落盘不依赖 ROM 数据，但正常 GUI 入口需先载入用户选定的 ROM；不能为打开存档编辑器而偷偷载入或改写默认 ROM。
4. **窗口标题**：`存档编辑器：` 尾部全角冒号逐字复刻（REQ-SAVE-005）。
5. **四阶段纪律**：表格编辑不直接写内存；“写入存档”不落盘；“保存存档文件”不得跳过未写入表格草稿。
6. **快捷键与菜单入口**：菜单项文本「存档修改器」（无快捷键）位于载入 ROM 后的“数据”菜单。
7. **衔接点**：纯协议位于 `src/fc_editor/codecs/legacy_save.py`；窗口生命周期和 ROM 可选解析位于 `src/dc_modifier/legacy_tools.py`。
8. **回归联动**：本模块不写 ROM，运行前后推荐 ROM 哈希必须不变；M17 双击公式只影响只读“双方速度”显示。
9. **存档差分原则**：槽写入只允许请求字段和对应校验和变化；活动敌方写入只允许已列数组中的目标字节变化；无法归因即失败。
10. **模拟器兼容性**：FCEUX 两份实际存档已通过；Mesen 输出只要恰为 8192 字节并符合同一槽校验即可读取。不同尺寸/布局必须拒绝而非猜测。
11. **不伪造字段**：下表机体 ID和金钱不在 SRAM；只读 ROM 推导失败时显示未解析，绝不把推断值写进机体图像或其他字节。
12. **参考差分边界**：当前实现可交付使用，但参考 EXE 写入黄金未完成前状态不得升级为“已对齐”；自动测试不得代填用户签收。
