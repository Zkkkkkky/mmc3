# ROM 内存分配与变长编辑对照

## 结论

参考修改器并不是把所有可编辑内容都限制在单条记录的原长度内。已归档的 M07 冷启动保存黄金表明，修改一条武器名称时，参考程序会重写整张名称指针表并重新布置连续数据池。新修改器应按资源的真实所有权选择下列策略，而不能统一使用“原槽等长”：

1. 固定结构字段：只改原位字节。
2. 指针表 + 独立连续池：重排池内全部物理记录，同步全部指针，保留别名。
3. 顺序记录池：重排后续记录，但总占用不得越过已验证池尾。
4. 带内部跳转或复合子对象的对象图：必须同时重定位入口、内部跳转和资源引用；证据不足时继续保持等长。
5. 扩展 Bank 分区：由现有容量规划器分配，不能侵占其他分区。

## 参考修改器证据

`M07/name_token/cold_start_01` 将“光束军刀”改为“光束军刃”，保存后由新进程重新打开并读回成功。单字段操作产生 2487 个变化字节、326 个连续变化段；除字段相关字节外，变化覆盖参考 ROM 的名称指针区 `$04AB32` 起和数据区直至 `$04B659`。这不是单记录原位覆盖，而是确定性的整表、整池重写。

## 本轮实现门禁

- 所有整池写入都先在内存中构造完整候选，再进行容量和结构验证，失败时零写入。
- 指针别名按原物理记录保持；同一别名收到不同草稿时拒绝。
- 未改文字尽量保留原 Token 字节，避免同字异码被规范化。
- 撤销、重做、工程保存重载和直接 ROM 重开后重新扫描动态指针。
- `$39:$887E`、标题 `$B0DE`、胜利文字 `$8289` 等池尾均为硬边界，不把相邻零字节或未知数据视为免费空间。

## 仍保留的结构门禁

### 分 Bank 章节事件

三个入口表和 `$1B/$1E/$1F` 数据现已建立线性入口与 `$55/$57/$58` 分支目标的联合视图。插入、删除或改变单条指令长度时，会在对应 Bank 的固定边界内移动后续字节、更新三张入口表并重定位所有已解析绝对跳转。Bank `$1B:$BE9B` 等同一字节存在两种合法解释的重叠区仍只允许等长参数修改；删除被跳转引用的指令、留下悬空目标或越过池尾会在写入前拒绝。Bank `$26` 独立行动池继续使用自己的 256 项对象分配器。

### 地图动画背景规律及部分动画脚本

背景规律包含动态指针、运行时长度和共享对象，不能套用简单文本池分配器。地图/敌我武器动画脚本的结构编辑现会同步重定位 `FE` 的绝对 CPU 循环目标，包括当前脚本内部目标、其他脚本跳入当前脚本以及后续整体移动的目标；被引用指令被删除或无法唯一识别时拒绝保存。`F8/F9` 在该动画解释器中是创建对象命令及资源参数，不会被误当作绝对地址改写。动态背景规律仍保持逐参数安全门禁。

### 剧情 `$37`

该组的指针表与正文分离，`$00` 仍是非文本结构并固定只读。`$01—$33` 的 51 个逻辑槽对应 34 条物理文本记录，现会在 `$9B4A—$9E27` 的 734 字节固定池内整体重排，保持共享别名与独立 `FF` 结束码。基准池已满，增长前必须先缩短同组另一条记录；不会越界借用相邻运行数据，也不会迁入扩展 Bank。

因此，“解除等长”指已确认的固定池或独立池可以重排，不代表取消总容量限制，也不代表对动态解释器数据进行猜测式搬移。
