# 旧修改器机体名称分配规则复核（2026-09-28）

## 结论

旧修改器不会把机体名称写进“初始配置”的剩余空间。它把机体名称作为独立资源整池重排，名称保存游标的硬上限为 CPU `$BEB0`；初始配置由另一套保存流程处理，其游标上限为 `$BF00`。两个数值相近，但属于不同资源映射，不能据此判定为同一池。

因此，新修改器应复制旧版的“资源隔离、整池重排、总量门禁”语义，而不是复制旧 ROM 的绝对地址：

1. 先只在当前 ROM 已验证的原生机体名称池内重排。
2. 原生名称池确实不足时，最后才通过选择器 `$13` 分配独立名称 Bank pair。
3. 不再借用初始配置池；初始配置容量不会因改名而减少。
4. 先前实验版本产生的“名称借部署尾部”ROM 仍可读取，下次改名时无损迁移到独立名称池。
5. 当前 255 个逻辑名称独立展开后占用 `1456 B`；在其上严格追加旧版已验证的 `6701 B` 净增长余量，所以新池总门禁为 `8157 B`。物理 Bank pair 的剩余空间不算旧版额度，也不向用户开放。

## 证据

### 旧程序保存代码

分析文件：`references/legacy_modifier/unpacked_unf.bin`。

- 字符串 `保存机体名称:空间不足!` 位于流偏移 `0x3574D0`，唯一代码引用位于运行时 `0x4F1C13`。
- 同一保存循环在 `0x4F1BDF` 比较累计游标与立即数 `$BEB0`；达到上限即进入上述错误路径。
- 该循环逐条累计名称长度、重建指针和正文，而不是对单个名称做原槽等长覆盖。
- `保存初始配置:空间不足!` 位于流偏移 `0x357B8D`，其独立保存循环在 `0x4FE20C` 与 `$BF00` 比较。它不是机体名称保存循环的后半段。

### 旧 ROM 实际布局

核对文件：`output/verification/legacy-unit-name-allocation-20260928/legacy-v51-original.nes`。

- 256 项名称指针表位于文件 `0x56031`。
- 名称正文由独立的 16 KiB 运行时窗口读取；当前唯一名称指针范围为 `$8083—$A469`。
- 按旧格式 `$F6` 结束码扫描，当前正文最高结束位置约为 `$A483`。
- 旧修改器保存上限 `$BEB0` 与当前结束位置之间约有 `0x1A2D`（6701）字节余量，所以旧 ROM 即使未扩容，也能直接保存更长名称。

进一步逐项核对 256 个指针后，旧版 V5.1 ROM 共得到 111 个不同指针。其中只有一组重复指针，来自 146 个空白/未使用槽；其余 110 个有效名称均为独立记录。尤其 `$09` 与 `$0A` 的名称指针分别为 `$8256`、`$A249`，并不共用。因此，“旧修改器把有效机体名称作为共用记录编辑”这一说法不成立。

这解释了“旧修改器未扩容也能改长”的现象：旧 ROM 本来就给名称资源预留了较大的独立池，并非它临时借用了其他模块。

## 当前 ROM 的差异与选择

推荐 ROM 的原生机体名称正文仅为 CPU `$9AF8—$9DAC`，容量 693 B，基线已经占满；旧 ROM 那段约 6.7 KiB 的名称余量没有原样保留下来。若强行把旧版 `$BEB0` 直接套到推荐 ROM，会越过武器名称、部署或其他资源，属于错误移植。

推荐 ROM 中仍可看到部分同名机体使用重复指针。这是当前 ROM 的压缩/转换布局，不是旧修改器的用户层编辑规则。新修改器读取时允许这种既有布局，但直接修改名称时必须按逻辑机体 ID 自动拆分，不能弹出“共用名称联动修改”确认，也不能把一个机体的改名传播给其他 ID。

| 方案 | 优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 借初始配置尾部 | 首次改名不登记扩展 Bank | 两模块容量耦合；不符合旧版资源隔离 | 停止新增，仅保留旧实验格式迁移 |
| 原生池超限即拒绝 | 最保守 | 满载基线几乎无法加长，用户体验差 | 不采用 |
| 原生池优先，超限后独立名称池 | 保留原生优先；扩容最后发生；名称与初始配置隔离 | 首次净增长可能需要登记一组独立 Bank pair | 采用 |

最终方案保留旧修改器最重要的安全属性：名称资源只消耗名称资源自己的容量，其他模块不会因为改名而被暗中压缩。

实现使用 `DCUNAME2` 头记录本次独立名称池的有效容量。默认推荐 ROM 首次需要迁移时写入 `8157 B`；随后无论保存、直接重开还是继续改名，都沿用这个门禁，而不是退回 693 B，也不会扩大到整组 16 KiB。旧实验版 `DCUNAME1` 仍按原格式兼容读取，避免破坏已经生成的派生 ROM。
