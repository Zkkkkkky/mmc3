参考 EXE 特技顺序为：无、加固定火力、直线地图炮2、范围修理、加固定火力并隐藏、抛射地图炮3、距离衰减地图炮、普通地图炮3、直线地图炮1、抛射地图炮1、十字地图炮、突击（移动远程）、抛射地图炮2、普通地图炮2、普通地图炮1、单体修理。原资源第 14 项有“跑”字，界面修正为“炮”。

头像正面使用 `$C0—$FF` 内 16 图块一幅；背景使用 `$80—$FF` 的 2KB 窗口。背景图库寄存器低位被 MMC3 忽略，因此背景图块起点高半的第 6 位必须保留并用于选择后半 1KB，不能把所有背景起点无条件截成 0—3。界面如实显示 2KB 内 1—8 位置。预览使用实际 CHR 和 FCEUX 色表，正面色号 0 透明叠在背景上。

## 容量和范围约束

人物属性池中 56 条唯一记录恰好占满 477 字节；头像池 71 条唯一记录占满 497 字节。200 个可读 ID（包含 UI 未列出的 `$C8` 保留项）有大量共享指针，不能因为修改一人就覆盖后面的机体或武器数据。

默认独立修改。改动唯一记录且长度不变时原位写入；其他情形只在已验证原数据池中去重重排，保留所有 ID（含 `$C8`）和保留标志。空间不足会阻止整个表单写入，保留草稿；界面提供明确的“同时修改共用属性记录”和“同时修改共用头像记录”选项，并列出受影响 ID。用户可先减少补正字段、复制/复用已有记录，或明确选择共享编辑。代码不会把程序中的零字节擅自当空闲区。

精神消耗是全局数据，还原一个人物不会顺带重置其他人物的消耗。头像上传修改的是 CHR 物理图块，所有使用同一图块的人物都受影响；界面会显示这一关系。上传后更改图库位置必须重新上传，避免向已不显示的位置悄然写入。

战斗/变形台词和自由扩展人物池仍未补齐；头像绑定及上传已可用，但背景图库 UI 采用可准确表达当前 ROM 的 2KB 地址方式，尚未模仿旧版“四幅一库”的换算显示。武器“复制属性与名称”和“还原武器属性与名称”以按钮名称限定范围，动画脚本保留当前内容。

后续续改已把主菜单“导出头像”从通用CHR工具替换为真实导出流程。选择根目录和人物后，在 `<十进制ID>：<名称>` 下生成参考EXE字符串确认的 `[背面].bmp`、`[正面].bmp`。两层分别按头像记录的背景/正面图库和位置读取16个CHR图块，以4×4排列和旧版素材四色写成32×32、24位、BGR、bottom-up BMP。输出读取当前工作ROM，Windows非法文件名字符会安全替换，已存在文件需先确认。格式与绑定已有自动测试；仍未取得参考程序动态导出的黄金BMP，因此不宣称逐字节完全一致。
