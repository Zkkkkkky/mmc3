# 2026-09-11 截图反馈：机体与初始配置

输入证据为根目录 `功能差异截图/数据-机体修改.png` 和 `QQ20260911-084436.png`。本轮补齐可核验的字段和图库编辑，不将原始图库称为合成机体图。

## 字段纠错

- 运行时 Bank `$24` 的 `$8064–$807B` 使用选择器 `$71`，把16字节属性记录复制到 `$04EE–$04FD`。
- 字节 `+0` 的低两位是地形类型，界面为0空、1陆、2海，3按保留原码保留。写入使用掩码，保留变形等高位。`$04:$9690–$96C5` 使用类型并把 `+1` 的特技复制到 `$77F7,X`。
- `+7` 是基础金钱，旧界面误标为“升级还需”。保留旧工程操作键 `upgrade`，只修正用户标签，不改变既有工程的目标字节。
- `+A` 为基础经验，后续字节 `+B` 保留。`$06:$850B` 从 `$04F8/$04F9` 读取经验，按等级和等级差继续运算。当前UI只开放原先已知的低字节，不替高字节赋予新语义。
- 特技使用完整字节显示；新DC有自定义组合值，不按旧版单一枚举重写。
- 工程保存时，如果地形低位与原始高位同时被修改，整字节交给原始补丁保存，防止位字段的覆盖记录吞掉高位改动。

## 图库与配色

`$04:$8E55–$8E94` 的加载代码已由现有签名约束：`+1..+3` 为机体色板，`+4..+6` 为碎片色板；`+7` 写入 `$04D0`（碎片页），`+8` 写入 `$04D4`（机体页1），仅大型机符号位为1时读取 `+9` 到 `$04D5`（机体页2）。这与用户旧版截图的三地址和两组三色吻合。

针对续改截图中“机体与碎片颜色是否对不上”的复核结果：两组顺序没有颠倒。运行时加载明确将记录 `+1..+3` 写入 `$0476..$0478`，将 `+4..+6` 写入 `$0479..$047B`；资料集 RAM 表也分别标为机体1图片颜色和机体1碎片颜色。旧版“盖塔龙”截图显示机体 `$26/$06/$20`、碎片 `$2A/$00/$10`，当前 ROM 同一记录逐字节一致。续改窗口截图选择的是“巴尔西昂修复型”，其记录实际为机体 `$22/$02/$20`、碎片 `$28/$18/$00`，不是同一机体之间的差异。为了消除 `$2`、`$0` 省略前导零造成的误读，界面已改成固定两位十六进制，并在每项旁显示来自随附 `FCEUX.pal` 的实时色块；测试另约束主体像素只使用第一组三色、碎片图库只使用第二组三色。

新“修改配色与图库…”窗口提供六色和已有图库编号编辑，确定写入，取消不写。小型机只改真实9字节记录中的后8字节，不把归一化第10字节写进相邻记录。大型机允许编辑两个主体图库。碎片2 KiB页对按低位忽略规则预览。原始池与48/64/80 KiB搬迁后的记录均通过当前资源布局定位。

数据库机体页原来仍把主体 CHR 原始图块条放在主画面，虽然状态文字声称已接通合成预览；该显示错误现已纠正。主画面直接显示真实脚本合成的完整机体，主体和碎片原始图库移到折叠技术详情。独立“机体拼图与配色”窗口则按参考工具的核对顺序重排：“主体拼图”左侧纵向显示主体原始图库，右侧显示带 8×8 网格的 128×128 合成结果；碎片图库与两段脚本原码放在各自页签，避免把两套颜色和素材混成一张机体图。

解析器支持当前记录实际使用的 `F3 dy dx` 有符号相对坐标、`FD 20 width` 行宽、`F9 count first_tile` 连续图块、直接图块和 `FF` 结束码；直接图块与 `F9` 共用同一行计数，才能正确还原大型机跨命令换行。全部255个当前主体记录均能完整解析，非空图像最大范围为16×13图块，没有超出旧版128×128画布。预览按机体三色和当前主体图库绘制，色号0保持透明黑底；大型机的 `$40—$7F` 图块落到第二图库。巴尔西昂修复型的实图证据为 `output/verification/unit-body-composition-0B.png`，整窗证据为 `unit-appearance-dialog-0B.png`。这次只增加确定性的只读主体预览，没有开放脚本回写或图像上传。

该窗口属于数据库事务：返回后数据库取消仍整体恢复。配色改变也可在主窗口撤销。共用外观记录的机体会一同改变；当前未实现独立拆分外观、拼图上传/压缩或碎片与物理武器解绑定。
