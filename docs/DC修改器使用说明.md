# 新DC篇完整修改器 3.0：图文使用说明

本工具用于编辑扩容后的 FC《第二次机器人大战》新 DC 篇 ROM。3.0 版恢复了参考 SRW2 修改器的窗口和操作顺序：先经过启动器，主窗口固定为战场地图，各类数据从“数据”菜单打开独立窗口；容量规划、机体包、音乐和工程验证等新功能集中在“扩展功能”或“工程”菜单。

> **安全原则：**修改器只在内存工程中编辑，并要求把结果保存为派生 ROM。当前打开的原 ROM 不会被覆盖。尚未完成地址和语义验证的旧版图像、动画、存档及全局参数只读显示，绝不猜测写入。

> **目录调整说明：**项目现已按 `src/`、`tools/`、`tests/`、`output/`、`docs/` 五个核心目录整理，并独立保留 `references/`。本次只调整文件归类和调用路径，修改器功能、ROM 格式、操作步骤及快捷键均未改变。

## 1. 启动与打开 ROM

推荐保持以下目录结构：

```text
扩容MMC3/
├─ output/
│  ├─ app/新DC篇完整修改器.exe              当前修改器
│  ├─ rom/DC_kuorong_464K.nes               推荐基线，464 KiB 托管资源池
│  ├─ patches/                               IPS 输出
│  └─ reports/rom-build/                     构建报告
└─ references/
   └─ rom/baselines/DC_kuorong.nes           兼容基线，200 KiB 托管资源池
```

单独复制 `output/app/新DC篇完整修改器.exe` 可以启动，不需要另装 Python 或 Qt；实际编辑仍需一份兼容 ROM。两个基线文件都是 1,310,736 字节，“464 KiB/200 KiB”表示可由修改器管理的扩展资源池，不是文件总大小。

![启动器](images/dc_modifier/00-launcher.png)

1. 双击 `output/app/新DC篇完整修改器.exe`，先出现精简启动页；页面只显示红色“作者 断月残心”和“进入修改器”按钮。
2. 点击“进入修改器”。此时主窗口为空，不会暗中自动载入 ROM。
3. 按 `Ctrl+O`，或选择“文件 → 打开”，再选择 `output/rom/DC_kuorong_464K.nes`。
4. 修改器会校验 iNES 头、Mapper 和受保护 Bank；身份不符时拒绝载入。

关闭主窗口会同时结束启动器会话；若仍有未保存修改，修改器会先询问是否放弃。

![未载入 ROM 的主窗口](images/dc_modifier/00b-empty-main.png)

载入成功后，“数据”“扩展功能”和“工程”菜单才会出现。窗口标题显示当前基线路径，末尾 `*` 表示内存内容尚未保存为工程或派生 ROM。

## 2. 主窗口：地图、初始配置与商店事件

![战场地图主窗口](images/dc_modifier/01-map-editor.png)

主窗口只承载地图工作流，左侧关卡列表和右侧地图在三个页签间保持不变：

- **战场地图：**选择真实图块后在地图上绘制。左键和右键是两套独立笔刷，可分别绘制或吸取；“全景适应”用于一次显示完整地图。
- **初始配置：**默认显示 ROM 活动 CHR 中的三组真实机体图标；高级部署区可编辑敌军、客军和我方出击位。
- **商店事件：**编辑该关已验证的地图触发点和商店记录。空白列表表示该关没有记录，不是读取失败。

左下选择关卡，右下确认当前地图草稿。切换关卡时，合法草稿会自动提交到本次内存会话；尺寸、坐标、容量或 Token 不合法时会阻止切换，并保留当前表单供修正。保存或输出 ROM 前也会自动尝试提交当前地图草稿。

地图、部署和触发点可在容量规划后自动搬入地图分区。单条记录不能跨越一个 8 KiB PRG Bank，界面会在提交前检查边界和总配额。

## 3. “数据”菜单：参考工具的独立窗口

“数据”菜单保持参考工具的顺序和快捷键：

| 命令 | 快捷键 | 当前行为 |
|---|---:|---|
| 数据库 | `Ctrl+D` | 机体、人物、武器等六页独立窗口 |
| 文字库 | `Ctrl+W` | 字表字符与已核对 ROM 地址的只读预览 |
| 地图动画 | `Ctrl+M` | 三页动画结构只读检查 |
| 文字转换 | `Ctrl+Z` | 文字与 Token 双向转换，不修改 ROM |
| 剧情事件 | `Ctrl+J` | 六页事件独立窗口 |
| 导出机体 | `Ctrl+F` | 导出所选机体 `.dcunit` 包 |
| 导出头像 | `Ctrl+L` | 打开 CHR 图像工具 |
| 属性计算器 | — | 使用当前人物、机体和武器做估算 |
| 存档修改器 | — | 读取存档结构；写入尚未验证，因此只读 |
| 其他 | `Ctrl+T` | 旧版全局参数分组只读展示 |

数据库和剧情事件窗口采用整窗事务：页内“暂存/应用”只是写入当前窗口会话；右下“确定”会自动提交仍未暂存的合法表单并保留全部修改，“取消”会恢复打开窗口前的 ROM 字节、资源分配和撤销历史。

### 3.1 数据库

![数据库](images/dc_modifier/02-database.png)

数据库包含“机体修改、人物修改、武器修改、战斗对话、其他修改1、其他修改2”六个页签，底部统一提供查找上一个、查找下一个、确定和取消。

- 机体列表采用 `[01]001: 名称` 格式。右侧保留旧版机体图像、碎片、图标、三色、类型和地址布局；活动 CHR 图标是真实 ROM 数据。
- 已确认的名称引用、移动、速度、强度、防御、HP、成长和两个武器槽可以编辑。“转到武器”会切换至武器页并定位关联武器。
- 上传/清除机体、碎片拼图、配色、机体类型和图像地址关系尚未完成验证，因此相应控件被禁用；鼠标停留可查看原因。
- 人物页开放真实名称引用及双方战斗音乐；武器页开放名称、射程、命中和三种地形攻击值。
- 战斗对话、其他修改1/2 目前只提供原始字节查看。只有完成差分验证后才会开放字段写入。

切换机体、人物或武器记录时会自动暂存合法改动；非法下拉值或字段会阻止切换。即使点过暂存，只要最后按“取消”，本次数据库会话仍会整体回滚。

### 3.2 剧情事件

![剧情事件](images/dc_modifier/03-scenario-editor.png)

剧情事件窗口包含“关卡设置、行动事件、劝降事件、地图事件、剧情对话、胜利文字”六页，并共享左侧关卡选择。“关卡设置”内还有“界面事件、回合事件、即时事件”三个子页。

- 已确认的增援、加入、阵营转换、撤退等动作只能使用等长兼容模板或等长原始字节修改，不插入、删除或重排脚本。
- 劝降页只开放 ROM 中 4 条已确认规则；其余占位槽不会伪装成可用事件。
- 剧情文本支持 Unicode 与原始 Token 无损往返。未知控制参数按原始字节保留。
- 标题拼图、胜利文字到关卡的独立索引等未验证关系明确保持只读，不建立猜测绑定。

### 3.3 文字库、地图动画与文字转换

![文字库](images/dc_modifier/04-font-library.png)

文字库按 16×16 网格显示已确认码表中的字符、字符代码和核对过的 ROM 地址。字符使用本机字体做可读预览；当前可以查看和定位，但“写入文字、替换全部字体、清空本页”等高风险操作尚未开放。

![地图动画](images/dc_modifier/05-map-animation.png)

地图动画恢复“地图动画、规律、动画调用”三个页签，并显示原始结构。动画指令及重定位规则未完成验证，当前为只读检查窗口。

![文字转换](images/dc_modifier/06-text-converter.png)

文字转换使用与剧情页相同的新 DC 码表。“文字转代码”和“代码转文字”都不会修改 ROM，适合在编辑剧情前核对 Token。

### 3.4 计算器、存档与其他

![属性计算器](images/dc_modifier/07-attribute-calculator.png)

属性计算器从当前工程读取人物、机体和武器，使用界面注明的确定性估算公式显示命中和伤害；结果仅供平衡参考，不会自动写回属性。

存档修改器可载入文件进行结构检查，但在校验和、槽位和字段语义全部确认前不提供保存。旧版“其他”窗口同样只复刻分组和当前值展示，不修改未经确认的全局表。

## 4. “扩展功能”菜单：新能力

新功能没有挤占参考工具的“数据”菜单，统一放在“扩展功能”：

| 入口 | 用途 |
|---|---|
| 战斗背景音乐 | 修改双方战斗曲，导入 `$9D–$9F` 扩展曲槽 |
| 机体导入与 CHR 图像 | 导入/导出 `.dcunit`，编辑已验证的活动 CHR 图块 |
| 扩展容量规划 | 自动给地图、机体和剧情分配 Bank 并接通运行时 |
| 工程概览 | 查看 Mapper、哈希和可用资源 |
| 变更与验证 | 查看字节改动并运行完整结构检查 |

### 4.1 自动容量规划

![扩展容量规划](images/dc_modifier/10-resource-manager.png)

推荐基线共有 464 KiB 托管空间。第一次需要扩展内容时，从“扩展功能 → 扩展容量规划”选择地图、机体和剧情额度，再点击“自动分区并接通”。推荐值为：

| 类别 | 推荐 | 规则 |
|---|---:|---|
| 地图 | `304 KiB` | 8 KiB 递增，共享给地形、部署和触发点 |
| 机体 | `48 KiB` | 可选 48/64/80 KiB；普通编辑选 48 KiB |
| 剧情 | `112 KiB` | 每 16 KiB 对应一个可变长文本组 |

三类配额按完整 Bank 固定边界，分配器会登记占用并禁止相互覆盖。规划完成后不需要手工填写运行时指针。`$61–$63` 是扩展音乐，`$64` 是双音频桥，`$7E–$7F` 是固定程序 Bank，均不会交给普通资源分配。

### 4.2 机体包和 CHR

![机体导入](images/dc_modifier/13-unit-import.png)

`.dcunit` 可以携带机体记录、名称、武器配置和可选连续 CHR 图块。导入前先核对目标 ID、共享记录提示和图块范围，再覆盖目标机体。

![CHR 图块编辑](images/dc_modifier/13b-chr-editor.png)

CHR 页提供真实 8×8 图块的放大绘制和 PNG/CHR 导入导出。NES 图块只有 0–3 四级像素索引，不自带颜色；批量导入前必须确认连续图块范围。

### 4.3 战斗音乐

![战斗背景音乐](images/dc_modifier/14-music-editor.png)

选择器可分别设置主动攻击曲和被攻击曲。扩展曲槽固定为 `$9D`、`$9E`、`$9F`，每槽占一个 8 KiB Bank。导入后必须运行完整检查，并在 Mesen 中验证播放、音效和切回旧曲。

## 5. 工程、撤销、验证与输出

“文件”菜单保持参考工具的简洁动线：

- `Ctrl+O` 打开基线 ROM。
- `Ctrl+S` 保存派生 ROM。第一次使用会要求选择新文件名；之后继续保存到该派生文件。
- `Ctrl+Alt+S` 在“工程”菜单中执行“ROM另存为”。

`.dcmod` 工程、IPS 和构建功能位于“工程”菜单：

1. 使用“工程另存为”建立 `.dcmod`，以后按 `Ctrl+Shift+S` 保存工程。
2. 按 `F7` 打开“变更与验证”，处理全部错误；合法地图草稿会先提交，无效草稿会阻止检查并保留表单。
3. 使用“导出IPS”或 `Ctrl+B` 一键构建 ROM、IPS、工程副本和 JSON 报告。
4. 使用 `tools/vendor/mesen-0.9.9/Mesen.exe` 进入实际关卡、剧情和战斗验证。FCEUX 2.6.6 不适合验证本 1 MiB PRG Mapper 194 ROM。

所有“另存为”和资源导出操作（工程、ROM、IPS、机体包、CHR、音乐 Bank、扩展资源及字库模板）的默认目录均为 `output/exports/`。即使当前打开的是 `references/` 下的旧兼容基线，生成文件也不会默认写回只读参考目录。

![变更与验证](images/dc_modifier/11-validation.png)

输出前会再次检查 iNES 头、受保护 Bank、分区边界、运行时入口、文本容量和事件长度。有错误时不会生成正式 ROM/IPS。`references/` 内的任何路径均为只读目标；选择当前基线或其他参考文件作为输出目标会被拒绝。覆盖已有派生 ROM 时会先建立时间戳 `.bak`。

按 `Ctrl+Alt+Z` 撤销、`Ctrl+Alt+Y` 重做。撤销当前合法地图草稿时，修改器会先把它作为一个事务提交并立即撤销；无效草稿会被保留并阻止撤销。存在任何地图草稿时，重做会被阻止，避免清空已有重做历史。`Ctrl+Z` 保留给参考工具的“文字转换”，因此不能再作为工程撤销快捷键。

## 6. 草稿、确定与取消

- **记录切换：**机体、人物、武器、文本和事件等页面在切换记录前自动提交合法草稿。剧情窗口切换关卡或外层总览时也遵循同一规则；非法草稿会把选中项恢复到原记录。
- **地图切换：**切换关卡或保存前自动提交合法地图草稿。
- **非法输入：**长度、容量、Token、坐标或必选项不合法时，切换和“确定”会被阻止，不会悄悄丢弃表单。
- **确定：**独立数据窗口会先提交各页尚未应用的合法草稿，再保留整个窗口会话。
- **取消：**无论页内是否点过“应用/暂存”，都恢复窗口打开前状态。
- **磁盘保存：**“确定”只改变内存；仍需保存 `.dcmod` 或按 `Ctrl+S` 输出派生 ROM。

## 7. 常见问题

### 进入修改器后为什么是空白

这是 3.0 的正常旧版动线。按 `Ctrl+O` 打开兼容 ROM 后，地图和数据菜单才会启用。

### 为什么一些看起来完整的按钮不能点

这些按钮按参考工具保留对应布局和入口，但其 ROM 地址或联动语义尚未完成差分验证。查看 tooltip 可以看到只读原因。真实预览不代表已允许写入。

### 点“确定”后原 ROM 为什么没有变化

“确定”只保留到内存会话。按 `Ctrl+S` 首次选择一个新 `.nes` 文件，或用工程菜单保存 `.dcmod`。修改器不会原地覆盖载入的基线。

### 文本或地图为何阻止切换

先阅读错误提示。常见原因是文本组超过 16 KiB、结束 Token 缺失、地图记录跨 Bank、部署坐标越界，或尚未进行扩展容量规划。

### 输出 ROM 可以重新打开吗

可以。有效规划和受保护签名都通过时可直接续改；若使用过高级未分配资源，仍建议以原 `.dcmod` 续改，以保留资源 ID、名称和分配意图。

## 8. 快捷键速查

| 快捷键 | 功能 |
|---|---|
| `Ctrl+O` | 打开 ROM |
| `Ctrl+S` | 保存派生 ROM |
| `Ctrl+D / W / M / Z / J` | 数据库 / 文字库 / 地图动画 / 文字转换 / 剧情事件 |
| `Ctrl+F / L / T` | 导出机体 / 导出头像 / 其他 |
| `Ctrl+Shift+O` | 打开 `.dcmod` 工程 |
| `Ctrl+Shift+S` | 保存 `.dcmod` 工程 |
| `Ctrl+Alt+S` | ROM 另存为 |
| `Ctrl+Alt+Z / Ctrl+Alt+Y` | 工程撤销 / 重做 |
| `Ctrl+B` | 一键构建 |
| `F7` | 完整检查 |

最后确认：基线 ROM 仍在原处、派生 ROM 使用新文件名、工程已保存、完整检查无错误，并已在 Mesen 中覆盖实际修改场景。`references/rom/source/新DC.nes` 是只读源素材，不能作为输出目标。对外发布时优先提供 `output/patches/` 中的 IPS、说明和 `output/reports/rom-build/` 中的报告，不直接分发可能受版权保护的 ROM。

## 9. 项目文档

目录整理不会改变 EXE、ROM、工程或快捷键的使用方式。维护与深入阅读入口如下：

- 根目录 `README.md`：项目概览、快速开始、目录结构和开发命令。
- `docs/DC修改器设计与实现方案.md`：分层架构、功能边界和后续扩展条件。
- `docs/提交记录.md`：已完成改动及对应验证记录。
- `output/pdf/DC修改器使用说明.pdf`：本说明书的生成版 PDF。
- `references/legacy_modifier/`：旧修改器与其配置快照，仅作逆向和交互参考，不是当前修改器源码。
