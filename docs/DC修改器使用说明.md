# 新DC篇完整修改器 3.0：图文使用说明

本工具用于编辑扩容后的 FC《第二次机器人大战》新 DC 篇 ROM。3.0 版恢复了参考 SRW2 修改器的窗口和操作顺序：先经过启动器，主窗口固定为战场地图，各类数据从“数据”菜单打开独立窗口；容量规划、机体包、音乐和工程验证等新功能集中在“扩展功能”或“工程”菜单。

> **安全原则（D1）：**编辑先在内存中进行；`Ctrl+S` 首次要求选择派生 ROM 文件名，不原地覆盖当前载入的基线。此后保存到所选派生文件，覆盖前先建立唯一时间戳 `.bak`；`references/` 始终只读。存档修改器仅写已由 SRAM 例程确认的槽位、校验和和活动战场字段；尚未完成地址和语义验证的旧版图像、动画及其余未知表只读显示，绝不猜测写入。

> **零经验用户入口：**随时按 `F1` 或选择“帮助 → 新手操作向导”。向导不要求理解 ROM 地址、Bank、指针或十六进制，会按“想修改什么”列出地图、部署、商店事件、机体、人物与头像、武器、剧情、字库、地图动画、存档等任务；选中任务后点“打开这个功能”即可直达对应页。尚未打开 ROM 时，仅开放“选择 ROM”和不依赖 ROM 的存档修改器，其余入口会明确显示“请先打开 ROM”。

> **复刻进度：**当前版本还不是 `SRW2_patched.exe` 的全功能一比一成品。菜单或窗口存在不代表功能已经对齐；逐项状态、参考控件和验收证据见 `docs/research/legacy-modifier/SRW2一比一复刻差异矩阵.md`。

> **机体拼图操作更正：**效果图已按旧修改器改为“左键直接编辑命中图块、右键直接删除命中拼图项”；下文早期记载中的“左键替换、右键分层菜单”已废止。

> **2026-09-11 视频反馈优化：**改进地图对象联动、超容后的规划入口、数据库可读性与资源预览、剧情全局作用域/全文检索、窗口缩放与刷新性能；修正字模的真实编码，开放固定字模编辑。详细落实与仍未完成的功能见 `docs/research/legacy-modifier/视频反馈优化验收.md`。本轮没有更换 ROM 布局或音频引擎。

> **2026-09-11 截图反馈续改：**按“功能差异截图”逐项核对，补齐机体字段与配色、人物属性/精神/头像、武器特技与双方动画、战斗/系统/道具文字、成长和商店编辑；关卡设置改用实际分 Bank 指令，地图动画与规律读取真实记录，初始配置默认展示三组图标。各项容量和未完成项目以下文为准。

> **2026-09-11 全量读取补充：**“扩展功能 → 完整ROM数据读取”一次索引机体、人物、武器、地图与部署、文字、动画和关卡事件，并提供覆盖当前内存镜像每个字节的 HEX 页。数据库和属性计算器默认选中有实际数据的记录；占位槽中的 `00` 会明确显示为 ROM 原值。

> **目录调整说明：**项目按 `src/`、`tools/`、`tests/`、`output/`、`docs/` 五个核心目录整理，并独立保留 `references/`。此前的目录迁移只调整归类和调用路径；当前功能变化以本说明和本轮验收记录为准。

## 1. 启动与打开 ROM

第一次使用只需记住五步：打开推荐 ROM → 按 `F1` 选择任务 → 在页面内选择对象并修改 → 点页面“暂存/应用”及独立窗口“确定” → 回到主窗口按 `Ctrl+S` 另存派生 ROM。这里有三级状态：页面“暂存/应用”只把当前表单交给独立窗口；独立窗口“确定”才交给主程序；`Ctrl+S` 才真正写出 `.nes` 文件。页面按钮因“没有变化”而变灰是正常状态；因容量或证据不足而受保护的入口会显示原因和安全替代路径。

为避免浏览长表格时误改数据，鼠标滚轮直接悬停在数字框或下拉框上不会改变当前值；需要用滚轮主动调整时按住 `Ctrl` 再滚动。所有模块的下拉弹层统一最多显示 10 行，超过部分使用滚动条，不再由人物、机体、武器或事件等长目录撑满屏幕。鼠标按下打开下拉后，即使保持按下并移动到其他条目再松开，也不会把悬停项误写成新值；弹层会继续保持打开，只有随后明确单击条目才会切换。点击上下箭头、键盘输入和方向键操作不受影响。

推荐保持以下目录结构：

```text
扩容MMC3/
├─ output/
│  ├─ app/新DC篇完整修改器.exe              当前修改器
│  ├─ rom/DC_kuorong_464K.nes               推荐基线，464 KiB 托管资源池
│  ├─ patches/                               IPS 输出
│  └─ reports/rom-build/                     构建报告
└─ references/
   └─ rom/baselines/DC_kuorong.nes           兼容基线，200 KiB 托管资源池
```

单独复制 `output/app/新DC篇完整修改器.exe` 可以启动，不需要另装 Python 或 Qt；实际编辑仍需一份兼容 ROM。两个基线文件都是 1,310,736 字节，“464 KiB/200 KiB”表示可由修改器管理的扩展资源池，不是文件总大小。

开发者已配置 `.venv` 并安装开发依赖后，可直接双击项目根目录的 `打包DC修改器.bat` 重新打包。脚本调用正式 PyInstaller 流程、运行 EXE 自检，并将新 EXE、SHA-256 校验文本和修改器映射表生成到 `output/app/`。窗口显示 `[OK]` 后再使用新 EXE；显示 `[ERROR]` 时应保留完整错误输出进行排查。多人开发时应先完成代码合并，再由一人在一台电脑上生成最终成品；不要对同一 `output/app/` 并行打包。

![启动器](images/dc_modifier/00-launcher.png)

1. 双击 `output/app/新DC篇完整修改器.exe`，先出现精简启动页；页面只显示红色“作者 断月残心”和“进入修改器”按钮。
2. 点击“进入修改器”。此时三页签工作区可见但没有关卡数据、编辑控件禁用；图块区是中性空位、画布不绘制任何地形，底部提示打开 ROM。不会暗中自动载入 ROM。
3. 按 `Ctrl+O` 或“文件 → 打开”选择 `output/rom/DC_kuorong_464K.nes`；保存时修改器会要求选择独立的派生 ROM，不覆盖推荐基线。
4. 修改器会校验 iNES 头、Mapper 和受保护 Bank；身份不符时拒绝载入。

点击进入后启动器窗口即销毁，不会作为隐藏窗口留在后台；关闭主窗口会结束修改器会话。若仍有未保存修改，修改器会先询问是否放弃。

![未载入 ROM 的主窗口](images/dc_modifier/00b-empty-main.png)

载入成功后，关卡列表出现实际地图，图块区和画布从 ROM 的 CHR/地图数据绘制，“数据”“扩展功能”和“工程”菜单才会出现。窗口标题固定为 `SRW2扩容版修改器V1.0：<当前 ROM 绝对路径>`（全角冒号）；未保存状态只在底部状态栏显示，不再改变参考标题。数据库等窗口关闭后，只刷新当前页面，其余隐藏页面在访问时更新。

机体等记录列表在条目未增减时就地更新，不再每次暂存都清空重建；批量刷新结束后仅加载一次选中记录。带草稿跳转机体/武器时先保存目标编号，再暂存与刷新，避免读取已失效的列表项。

## 2. 主窗口：地图、初始配置与商店事件

![战场地图主窗口](images/dc_modifier/01-map-editor.png)

主窗口只承载地图工作流，左侧关卡列表和右侧地图在三个页签间保持不变。全局界面采用低饱和灰白底与青灰强调色：菜单、页签、分组、输入框、按钮、列表和滚动条使用统一的圆角与悬停/选中状态，减少大面积亮蓝和高反差渐变造成的视觉疲劳；各分区边框采用中等对比度，分组标题使用浅青灰标签底，当前页签增加细青灰强调线，以接近旧界面的区域辨识度而不恢复刺眼的亮蓝渐变。界面表面分为三层：窗口使用柔和灰蓝底，一级模块使用近白卡片，模块内部的分组使用浅青灰卡片，更深一层恢复更轻的近白底，因此嵌套区域不会再融成同一块背景。输入框默认近白，悬停与焦点使用渐进青灰边框；只读字段使用独立浅灰蓝底，禁用字段再降低对比度。选中按钮、列表/树表选中行、表头、进度条、滑块、分隔条和消息框也使用同一色系与明确状态。

该主题同时覆盖主窗口、数据库六页、地图三个内嵌页、剧情/行动/劝降页面、完整 ROM 数据页以及所有独立工具和编辑弹窗；树表、列表、普通表格、多行文本、禁用输入、单选/复选、分隔条、工具提示和底部按钮栏采用同一套状态颜色。弹窗中的“确定 / 保存 / 应用”自动使用青灰主按钮，“删除”类操作使用浅红危险按钮，取消保持中性，避免所有操作视觉权重相同。下拉框保留 Qt/Fusion 原生箭头，不用自定义空白按钮区遮盖；列表选中项无论是否持有键盘焦点，都统一使用深青灰底和白字。地图事件与商店未选中时仍分别保留紫色、绿色文字辨识类型，选中后不会再出现白字浅底。地图页保留旧版的原始边距、左右比例和左上对齐，不再用主题留白挤压工具区或画布；关卡列表使用 13 px 字号和 18 px 紧凑行高，在维持中文可读性的同时让同一高度多显示若干关卡。黑底像素素材仍保持原色，不因主题美化改变游戏资源。容量状态的完整悬浮详情按项目换行，避免单行提示横跨或超出修改器窗口。参考 Windows 125% DPI 下，打开 ROM 后整窗物理高度为 876 像素，与旧修改器一致：

界面验收不是只看顶层窗口：当前自动布局审计会递归渲染启动器、主窗口各状态、数据库六页、剧情六页、动画三页、ROM 浏览八页、机体拼图三态以及图标、头像、精神、条件、代码、成长、图块属性、碎片位置、武器运动等二三级弹窗，并单独保存复制/粘贴前后的机体、人物、武器右键菜单。100% 与 125% 缩放各检查 72 个可见状态；标准为无文字截断、无控件挤压、无意外横向/页面级纵向滚动条。Qt 默认英文按钮会在弹窗显示前统一转换为“确定、取消、关闭、保存、应用、是、否”等中文，但自定义动作文字保持不变。碎片位置编辑把坐标、图块号和翻转状态分成清楚的两区；武器运动模拟把宽高、X/Y、采样间隔拆成三行，不再把长标签与复选项挤在同一行。鼠标左/右键、双击、拖拽、组合键、条件启用项仍按旧版递归证据和自动回归分别验证，界面重排不改变 ROM 写入语义。

- **战场地图：**选择真实图块后在地图上绘制。左键和右键是两套独立笔刷，可分别绘制或吸取；两侧画笔预览各使用 32×32 紧凑框显示一个单图块，不再放大到 64×64，也不会把同一图块重复平铺成 2×2。“全景适应”用于一次显示完整地图。关卡标题使用旧版游戏截图一致的宋体点阵风格和每字 40 像素单元显示；主地图页与剧情窗口共用同一渲染器。全部地图槽位会显示完整标题，不再因为通用 ROM 码表缺少“街”、数字或占位标签字符而漏字，也不会把 12×12 编辑字模机械放大成 4×4 粗块。

地图页左侧的“地图高度/地图宽度”现在可直接输入或用上下箭头调整，范围均为 1—32。尺寸变化先在当前地图草稿中重排地形格并刷新画布和 RLE 容量提示。未接通扩展地图池时，地形保存完整沿用旧修改器的三级重排方式：100 张地图按编号连续编码到三个 PRG Bank；当前 Bank 放不下下一张地图时，会更新 ROM 中的两个运行时分界并把该图及后续地图级联搬到下一 Bank，同时整体更新指针。每个 Bank 可使用到已验证末尾 `$C000`，但单张地图不能跨 Bank。悬浮详情中“所在 Bank”表示当前地图经本次规划后所属 Bank 的占用，“三 Bank 合计”是三个地图 Bank 的已用/总容量之和；合计值不代表可将零散空间拼成一张跨 Bank 地图。为避免默认窗口宽度下截断，常驻行紧凑显示地图号及“`Bank`/“三 `Bank`”/“整图迁移”。推荐 ROM 初始常驻行为“图 `$00`｜`Bank 6709/6722`｜三 `Bank 14474/17730 B`｜整图迁移”；地图 `$00` 从 27 列增到 28 列时会自动把分界 `$22/$2A` 调整为 `$21/$29`，状态变为“图 `$00`｜`Bank 6453/6722`｜三 `Bank 14520/17730 B`｜整图迁移”，可直接保存。只有三级动态重排仍无法容纳时才要求容量规划。接通扩展地图池后继续显示统一共享池的已用/总容量。高级地图数据窗口中的同名控件与主界面同步，保留前导字节等扩展操作。

“回血”列来自实际回合结束程序，不是按图形猜测。Bank `$0A:$8FA0—$9009` 会读取当前地图格并取低四位，在 `$8FCA` 与一个全局图块编号比较；原值为 `$0A`，所以图库 A—H 的位图 A 都是回血格。游戏只支持一个全图库共用的回血图块，勾选另一行会自动取消上一行，也可以取消全部回血地形。命中后程序以最大 HP × `$1E` ÷ `$64` 计算，原值即30%；母舰搭载从同一计算入口执行，因此“回复%”也是地形与母舰共用的全局比例，可设为1%—100%。

图库 A—H 的位图0均按参考修改器与游戏画面固定使用背景表 `$0F $30 $10 $00`，在顶部图库、左右画笔、属性窗口和地图实例中显示为同一个灰阶背景块；不会再随图库主题错误显示为绿色、紫色或太空色。

所有游戏内颜色预览共用同一份随程序附带的 `FCEUX.pal`，测试会逐字节检查内置 64 色表与该文件一致。地图、地图图标、机体主体、碎片和人物头像均通过这份色表显示；透明/背景索引统一按 `$0F` 处理。人物头像正面使用记录中的三个真实色号，背景层按像素索引 1/2/3 使用 `$20/$10/$00` 亮/中/深灰，合成时保留两层各自色表；通用 CHR/字模编辑器使用便于辨认位平面的工作色。

地图、部署和触发点可在容量规划后自动搬入地图分区。单条记录不能跨越一个 8 KiB PRG Bank，界面会在提交前检查边界和总配额。

### 3.2 数据库

![数据库](images/dc_modifier/02-database.png)

数据库包含“机体修改、人物修改、武器修改、战斗对话、其他修改1、其他修改2”六个页签，底部统一提供查找上一个、查找下一个、确定和取消。

- 原先集中在窗口底部的“内存分布”入口已经移除。现在每个数据库页签底部都有自己的“本模块内存”栏；点击“本模块明细…”可查看 ROM 地址、已用/容量、净增长空间、写入状态和共用关系。人物页的 Bank `$24` 八资源复合块为 `9529/15184 B`、当前共享余量 `5655 B`，由人物属性、机体属性、武器属性、普通名称、战斗名称、机体名称、武器名称和 32 关初始配置共同占用。普通名称、战斗名称和人物属性现已按旧修改器接通八资源整体重排，不再受 `395 B`、`477 B` 当前切片的假容量限制；任一记录增长时会同步重建目录、后移后续资源并重定位内部指针。头像配置则与机体战斗外观共用另一段 Bank `$04` 尾区，当前为 `2194/2992 B`、可净增 `798 B`。系统文字的 249 B 仍不能借给战斗对话；固定结构显示“可改值、不可增长”，表示现有字段可以正常编辑，并不表示该功能被禁用。
- 数据库字段的编码、值域、指针关系和运行时含义以旧修改器实测及游戏读取代码为准。固定字段仍在原位等长写入，已有安全池的变长资源在各自池内重排。机体名称按“未扩容 ROM”优先处理：未修改时不占扩展区；当前 255 个逻辑名称按旧版独立记录语义计为 `1456 B`，并严格保留旧修改器实证得到的 `6701 B` 净增长余量，总门禁为 `8157 B`。原生 CPU `$9AF8—$9DAC` 确实放不下时，最后才通过资源选择器 `$13` 分配独立名称 Bank pair，但不会把整组 16 KiB 都冒充成旧版可用容量。旧修改器的名称池本来就是独立资源，其保存上限为 `$BEB0`，并未借用初始配置；因此新版也不减少初始配置容量。先前实验版借部署尾部的 ROM 仍能读取，并会在下次改名时无损迁移。保存前会校验指针、扩展资源登记和受保护代码，越界或未知布局会整笔拒绝。
- 数据库首次打开只读取当前可见的机体页，人物、武器、战斗对话和两个“其他修改”页在第一次切入时读取；窗口关闭后会保留并复用已经解析的界面，未修改时“取消”不再重复扫描全部文字、列表和机体图像，因此随后再次打开和关闭可以立即完成。各模块底部的内存信息按当前 ROM 修订号共用一次完整扫描，重复切页不再重新解析全数据库；任何真实编辑、撤销、重做或取消回滚都会使缓存失效并重新计算。撤销补丁也改为先用原生块比较跳过未变化的 ROM 区域，不再为改几个字节逐字节扫描整份 ROM。若期间从其他窗口修改了 ROM，数据库会在下次打开时自动重新同步；这些缓存不会改变“确定”保留、“取消”整窗回滚的事务规则。

- 武器页列出完整的 `$01—$FF` 武器槽，开放名称、特技、射程、命中、距离修正方式和三种地形攻击值，并用“我方武器动画 / 敌方武器动画 / 使用此武器的机体”三个子页签显示双方实际动画脚本和反向引用。属性指针旁会列出共用同一六字节记录的武器 ID；直接修改、复制、还原或编辑共享动画参数时，会列出全部受影响武器并默认取消。“代码编辑”和指令右键菜单支持对当前单武器动画插入、删除及完整脚本结构编辑；右键“编辑”只打开当前指令参数，右键“插入”严格恢复旧版实测的 12 项目录：F4 声音、F0 颜色、F2 光束图库、F3 光束规律、E0/E1 图库区、FD 移屏、FE 跳转、F9 创建物体、42/C2 运行规律、等待和 FF 结束，不再混入地图动画专用的 E2/F6。选定新指令后才进入参数页。F2、E0、E1 均显示旧版 256 项图库地址；F2 确定时询问是否为大型机体专用，否/是分别生成 `$F2 $03 $01` / `$F2 $04 $01`。F3 固定 `$F3 $22`，仅显示 `$01—$FF` 的 255 项命名规律。FE 同时显示重复次数和旧版 `000—199` 指令编号，保存为真实 CPU 目标并在重排时自动重定位。F9 严格是四字节“物体编号（00—FE）+ 初始 X/Y 坐标”；42/C2 是独立五字节规律，提供 `42/C2`、规律1/规律2和三列各 252 项命名运行规律，实测规律1/2 状态码为 `$69/$6A`。超过原指针槽时会移动后续脚本并更新指针，被引用指令被删或目标无法证明时拒绝保存。“规律”打开武器专用的光束组图、两套物理运行和物理图片规律四个页签；当前构建可浏览、查找、复制、导出及编辑工程名称，并已恢复四页共用的“运动规律模拟器”和光束/物理图片两类拼图入口。模拟器沿用旧版的黑底红轴、宽高、X/Y、鼠标跟随、移动、开始/结束及 X/Y 规律代码布局；直接读取当前规律，能离线展开普通坐标字节和 `$83` 计数循环，遇到依赖运行时状态的控制码会停止而不猜测。拼图读取当前记录的隐藏 X/Y 前置字节、真实 CHR 图库和图块命令，支持 `00/80` 映射、图块编号及水平/垂直翻转预览。旧版保存黄金已经证明四库不是四个独立定长区，而按“物理图片→光束组图→运行规律1→运行规律2”共用一个目录链接池；当前基准使用 `12141/12256 B`、剩余 `115 B`。规律代码现可在该共享范围内变长或缩短，保存时原子移动后续库并更新目录和记录指针；光束与物理图片的隐藏 X/Y 前缀也可用十六进制控件独立修改。代码、坐标、名称和容量都先停留在窗口草稿，取消零写入，确定一次提交并可撤销；超容或非法十六进制整笔拒绝。相同物理指针的别名记录究竟由旧版联动还是写时复制仍在取得保存黄金，图块编号增量控件也尚未恢复，因此武器规律仍不能标为完整还原。“动画测试”生成独立测试 ROM 和存档，不覆盖原 ROM。当前 `$01—$FF` 已满，“添加”只说明武器记录容量，不伪造新武器槽。
- **规律别名、图块增量与缩短口径更新：**旧版对已知共用光束记录 `$D6/$E1/$E2` 的单项保存黄金已经确认“写时复制”，不是联动修改：只编辑 `$D6` 时会为它建立独立 4 B 正文，`$E1/$E2` 继续共用旧正文，后续三库随池增长整体迁移。产品已按同一规则实现，复制/导出也读取当前未提交草稿。两套运行规律现在都恢复“图块编号增加”：输入十六进制增量后，只增加规律中的图块编号，循环、音效、跳转和结束参数保持不变；运行规律1/2 的旧版保存结果均已逐字节匹配。四库首记录缩短也已分别取得旧版整 ROM 黄金并由产品逐字节匹配，释放的空间会回收到同一共享池、后续目录向前移动、旧尾部清零。本条取代上一段中“别名语义、图块增量仍待验证”的旧状态；当前剩余缺口是引申窗口深层动作。
- **武器拼图草稿回写：**光束拼图和物理拼图不再是只读预览。光束图库按旧版使用 `40/80` 两段起点，物理图库使用 `00/80`；切换起点只改变图库显示编号，记录仍保存逻辑图块。旧版动态验证确认图库为左键选块：物理效果图左键修改当前项的图块和位置、右键切换当前项水平翻转，光束效果图左键替换命中项、右键删除命中项，没有“图库双击追加”或额外图块参数弹窗。物理整图水平/垂直翻转会以原点为轴改变全部坐标并切换对应翻转位。拼图“确定”只把结果交回规律窗口草稿并立即重算四库共享容量；拼图“取消”不改变草稿，数据库“取消”仍保持 ROM 零写入。物理拼图已改用旧版最短编码，可在隐式递增、保持、显式换图和三种位移形式间选择；现有记录无操作重编码以及整图水平/垂直翻转均与旧版字节完全一致。光束拼图使用独立的 `FE/F3/FD/F8/F9` 编解码器，压缩记录也可替换或删除图块；未操作时保留原始字节，发生编辑时按已验证语法生成紧凑记录并再次解码核对坐标、顺序和图块。旧版对同一画面的规范化字节选择仍在补齐，所以 M07 尚不能标为完整还原。
- 武器射程和特技共用一个字节，同时修改后保存工程会保留两部分；重新打开 `.dcmod` 不会丢失特技高位。
- 武器页可反查使用它的机体，并跳回对应机体；`.dcunit` 包只从“扩展功能 → 机体导入与CHR图像”导入/导出。数据库机体列表右键“导出机体”固定使用参考工具的当前机体五张 BMP 协议，两种格式不再混用。
- 战斗对话按当前 ROM 的四个真实文本组和编号列出正文，随机台词另列分支；右侧可在“按列表”和“按内容”两个视图间切换，内容视图以 `++` 分隔同一记录的随机分支。选中后直接改文字并暂存，两个视图同步更新。控制 Token、F8 随机目录和未改字形的别名编码保持原样；同一物理正文的全部引用一起生效，若多个引用存在不同草稿会阻止提交。
- 战斗对话允许在同一 8 KiB Bank 的已验证安全文字段内重排：Bank `$2A` 的 00/01 组共享 5432 字节，Bank `$0E` 的 04/05 组共享 6294 字节。基准 ROM 两池都已占满，所以要增长一条文字，必须先在同一 Bank 缩短其他文字释放相同或更多字节；两个 Bank 不能互借容量。界面状态会显示当前 Bank 的占用、容量和剩余字节。提交会原子更新正文、F8 子指针和根指针表，超出总容量、单条无法放入安全段或无法编码时保留草稿并零写入；Bank `$2A` 的系统文字及 Bank `$0E` 的非文字间隙不会被当作容量。
- 系统文字和道具说明仍使用同一编辑方式，但继续限于各自原记录容量，不参与战斗对话重排。可运行 `.\.venv\Scripts\python.exe tools\report_m08_battle_text_compatibility.py` 复核安全池、别名、保护间隙、重开和超容原子拒绝；报告位于 `output/verification/m08-battle-text-compatibility.json`。
- “其他修改1”严格按参考修改器保持同屏四列：系统文字、成长方式、升级经验、武器距离命中补正，不拆成产品自创的任务页签。经验表显示等级 1—99 的升级阈值、当前累计和还需经验；可编辑升级阈值以及 4×16 武器距离命中补正，后一级累计经验低于前一级时会拒绝提交。成长表按编号 201—253 显示每级 0—15 的数值，“成长修改(16进制快捷修改)”可一次编辑前 60 级的 60 位十六进制串，等级 61—99 保持原值。214—253 在当前 ROM 共用一条记录，修改会同步影响共用编号；低于 201 的固定成长值在人物/机体属性中设置。当前受支持 ROM 的运行时比较指令、99 项累计经验和每条 50 字节成长记录共同确认等级上限已是 99，界面会显示真实值。旧版 3778 字节的 60→61 样本来自当前产品不支持的 `audit.nes`，不能套用；“更改等级上限”可点击查看 99 级容量诊断，但超过 99 级的未验证重排不会写入。系统文字“添加”同样会解释固定指针表/文字池边界并保持零写入。可运行 `.\.venv\Scripts\python.exe tools\report_m09_other1_compatibility.py` 统一复验 4×16 命中、99 项经验、221 条系统文字、53 个成长槽、单半字节/60 位快捷编辑、214—253 共享和 99 级兼容性；报告位于 `output/verification/m09-other1-compatibility.json`，其中嵌入原 `m09-level-cap-compatibility` 结论。
- “其他修改2”按参考窗口恢复为同屏双栏：左侧“道具”面板同时显示 24 项表格、独立的名称/价格编辑框和当前道具说明；右侧“商店”面板同时显示 F0—FE 列表、商店设置和七段店员对话，不再分成三个额外子页签。选中道具后，名称、价格和说明会联动到同一记录。名称使用新 DC Token 编码并整体重排固定的 184 字节文本池，局部改名会保留未改字形的原始 Token 别名，“还原”则精确恢复指针和文本池字节；单独改价格不会触碰名称指针或文本池。价格按旧窗口显示为 ROM 原值的 10 倍，因此输入必须是 0—99990 之间且能被 10 整除。24 项价格已逐项通过参考程序“单字段修改、保存、关闭、全新进程重开”验证，确认从 `0x15723` 起按小端 `u16` 连续排列。名称无法编码、总长度超限或价格非法时会阻止“确定”。
- 有效商店可修改商品、店员和对话起始编号。当前 ROM 的 F0—F3 各有四件商品、F4 只有一件；F4 的商品 2—4 明确禁用，底层编解码器也会拒绝伪造四件商品的补丁。列表严格按旧修改器显示 F0—FC、FE，不显示旧版没有的 FD。F5—FC、FE 的商店元数据与地图事件指针表重叠，设置区保持禁写并直接说明会影响什么；但旧版这些行仍能编辑的七段系统文字已经保留，对话区继续可用，固定选择系统文字 195—201。当前字段目录共有 57 个禁写候选：九个无效行的 54 个店员/商品/对话起始字段，加上 F4 越界的 3 个商品栏。七段对话与“其他修改1”的系统文字是同一物理记录；两页同时修改同一段时会阻止提交，先放弃一页草稿再保留另一页即可。无效行只保存七段文字时，程序会保持地图事件 32 项指针表和商店目录逐字节不变。可运行 `.\.venv\Scripts\python.exe tools\report_m10_other2_compatibility.py` 复验 24 名称/价格/说明、名称池重排和超容拒绝、F0—F4 三类单字段差分、F5—FC/FE 的 63 个安全对话入口及地图事件重叠元数据禁写；报告位于 `output/verification/m10-other2-compatibility.json`。

剧情事件窗口包含“关卡设置、行动事件、劝降事件、地图事件、剧情对话、胜利文字”六页，支持缩放。只有关卡设置和地图事件显示章节侧栏；行动与劝降为全局表，不跟随当前章节误筛选。“关卡设置”内还有“界面事件、回合事件、即时事件”三个子页。三个子页只显示参考式自然语言列表；右键“编辑”只打开当前操作码的专用参数窗口，不显示命令目录，也不能误换指令类型。右键“插入（接上/接下）”只打开旧版三页“事件指令”目录，窗口中不显示当前指令参数；单击目录中的命令后，才继续打开该命令自己的参数窗口，确定后完成插入。三页内容严格按旧版划分：第 1 页为触发条件，第 2 页为执行事件 1—4，第 3 页为执行事件 5—7及事件结束；按钮分组、合并命令和文案沿用旧版。右键菜单按参考顺序显示插入、添加增援、编辑、代码编辑、剪切、复制/全部、粘贴/全部、删除和清空；单条编辑、结构插入/删除、剪切和粘贴均接入当前章节事务。人物、头像、机体、道具、音乐、剧情文字组、事件开关、移动限制和状态位等具名参数使用下拉框并显示名称或位含义；坐标、数量、等级、HP、金钱、帧数和地址等真正数值才使用数字框，鼠标停留可查看原始十六进制值。事件列表不再拼接难懂的字段名和十六进制原码，而按旧版显示“判断：……？”、“是/否：转：…”、“文字显示：内容…”、“播放我方/敌方地图音乐…”等可直接阅读的结果；原码仍由独立“代码编辑”入口查看。独立行动表也只在主页面显示自然语言指令列表，不再内嵌当前原码和重复操作按钮；全部编辑、插入及代码操作从右键菜单进入，其中“插入（接上/接下）”使用同一两段式流程。劝降、地图、剧情对话和胜利文字列表支持右键打开相应编辑器。

- 关卡设置从真实的分 Bank 指针读取三类事件，显示当前关卡的完整指令列表、文本摘要和原码。可修改参数或整条合法指令，也可插入、删除；保存时在对应 Bank 内重排并维护入口和绝对跳转。第一关的初始配置表为空，出击通过界面事件安排；地图上的空配置列表并非遗漏了事件部署。
- 已确认的增援、加入、阵营转换、撤退等动作只能使用等长兼容模板或等长原始字节修改，不插入、删除或重排脚本。
- 行动页直接读取 Bank `$1A:$9BC0` 的 256 项指针和 Bank `$26:$A000—$AABE` 脚本池，列表 ID/名称与默认“行动名称”配置对应。基准 ROM 去重后为 45 个有效物理脚本，使用 2541 / 2751 字节，可用 210 字节；`$03/$FF` 的真实共用指针保留。
- 行动指令及三类关卡事件均可通过右键复制、编辑、代码编辑、接上/接下插入、删除与清空。Bank `$26` 独立行动表会重排 256 项对象池；界面/回合/即时事件分别在 `$1E/$1B/$1F` 固定池内移动后续记录并更新三张入口表。两条路径都会重定位 `$55/$57/$58` 绝对跳转；容量不足、删除被引用指令、目标悬空或命中 `$1B:$BE9B` 等重叠解释区时会在写入前整体拒绝。
- 劝降页只开放 ROM 中 4 条已确认规则；其余占位槽不会伪装成可用事件。
- 剧情文本支持 Unicode 与原始 Token 无损往返。当前开放 `$32/$33/$36/$37/$38/$39/$3A/$3B` 八组共 1837 个索引；未知控制参数和未改字形的 Token 别名都按原始字节保留。`$32/$33/$36/$38/$39/$3A/$3B` 即使尚未建立扩展计划，也会在各自已验证的原 Bank 安全池内自动重排指针和正文；总池不足时才需要缩短同组文字或使用容量规划。`$39` 严格止于 `$887E`，不会覆盖相邻运行数据。`$37` 是分离指针/数据布局：`$00` 指向非文本结构并固定只读，`$01—$33` 共 51 个逻辑槽对应 34 条物理文本记录，会在 `$9B4A—$9E27` 的 734 字节固定池内整体重排并保持别名。基准池已满，因此增长一条前必须先缩短同组另一条。
- 剧情/胜利页可选择文本组、搜索完整正文；列表优先显示中文摘要，双击直接打开文字编辑。码表设置和 Token 解析默认折叠，需要时再展开。
- 关卡设置左侧“初始胜利文字”已绑定 Bank `$3D:$8000` 起的 13 条连续关卡记录，不再使用占位文案。前 13 个已验证关卡支持按当前正文字节数等容量编辑；切换关卡或点外层“确定”会自动提交合法草稿，无法编码、含提前 `FF` 结束码或改变容量时会保留输入并阻止切换。备用关卡保持明确只读。
- 直接修改 Unicode 页后，不必先点“编码到原始 Token”；切换记录或外层“确定”会自动编码并提交合法草稿，无法编码或超出容量时会阻止切换。如果 Unicode 和原始 Token 两边都改过，会先报冲突并保留两份输入；点“文字编码到Token”表示明确以 Unicode 内容为准。
- 对没有语义模板的事件指令，“结束本事件组”只切换操作码高位，其余原始字节保持不变并可撤销。
- 同一章节脚本物理指令可能同时出现在关卡设置和地图事件页；两页同时有草稿时，直接应用和外层“确定”都会在写入前报冲突，防止后一页覆盖前一页。独立行动表位于 Bank `$26`，不与这些 Bank `$1B/$1E/$1F` 章节脚本共用物理指令。
- 标题拼图预览已改为直接解析 ROM 真实图块：32 项指针表在文件 `0x16111`，每关三个 64 图块 CHR 页表在 `0x159AE`，不再用关卡列表文字模拟。因此第 1 关黑框显示的是 ROM 内实际“克鲁泽之影”，而不是列表占位名“伏击之战”。根据用户提供的原版/产品并排截图，标题像素索引 1/2/3 也应为亮→暗 `$20/$10/$00`，即 `#FCFCFC/#BCBCBC/#747474`：白色是主笔画，深灰是边缘。标题拼图窗口按参考版恢复为顶部坐标/宽度和刷新按钮、中部黑底标题预览、下部三块图库横排；原始 `FE X Y 宽度 + 两行图块 + FF` 脚本移入“查看拼图代码”弹窗，避免普通界面拥挤。当前只允许保持原记录字节数的原位写入，指针表不变。
- 底部“检查剧情；界面事件和回合事件；即时事件；行动事件，劝降事件和地图事件剩余空间”已经开放。参考 EXE 文件偏移 `0x1A0C57` 的处理器与 `0x194936` 容量函数证明点击后使用标题“提示”的消息框；产品同时按当前 ROM 的真实物理池列出八组剧情文本、界面+回合事件 Bank `$1E`、即时事件 Bank `$1B/$1F`，以及 Bank `$26` 独立行动池的占用/容量/剩余。劝降仍只报告 4 个已验证槽，地图事件仍是分 Bank 章节脚本的条件视图。检查只读，不修改 ROM；合法的窗口草稿会先按整窗事务暂存，非法草稿会阻止检查。
- 可运行 `.\.venv\Scripts\python.exe tools\report_m14_scenario_compatibility.py` 复核参考 72 控件树、96 组/4274 条分 Bank 事件、2637 条兼容全局事件、256 项独立行动表及其变长重排、4 个安全劝降槽、八组 1837 文本索引（含 `$37` 的 51 可写槽+1 只读非文本槽）、13 条初始胜利记录、32 组标题拼图和事务/撤销边界；报告位于 `output/verification/m14-scenario-compatibility.json`。`passed=true` 与 `delivery_status=implementation_complete` 表示实现侧范围闭环，仍不代表参考 EXE 动态黄金或用户验收。

### 3.4 文字库、地图动画与文字转换

![文字库](images/dc_modifier/04-font-library.png)

文字库按 16×16 网格显示 ROM 实际字模、码表字符和地址。已修正旧版预览的错误：每个 18 字节字模是三条 4×12 竖条，每字节存两行的四位像素，0 表示前景；不是连续 144 位。未映射且 18 字节为统一填充的安全空槽会显示为与网格一致的低对比度空格，不再把全 `00` 填充误画成刺眼的白色实心块；选中后右侧标题会明确显示“未使用”。已有映射或包含真实点阵的字模仍按 ROM 原样预览。文字库仍用于真实 ROM 固定字模读写；关卡标题预览采用独立的旧版标题显示路径，避免不完整通用码表造成整字缺失。

当前界面将字模矩阵恢复为连续深色预览面，行列标题使用浅灰蓝底，当前字模以蓝绿色底和暖金描边双重标识，避免仅靠轻微底色区分而看不清选中项。右侧修改区收紧为“字库页、当前字形、批量操作、字形信息”四个层级，主操作使用蓝绿色、清页使用低饱和警示色；默认窗口高度可完整显示所有操作，无须滚动查找按钮。

在兼容 MMC3 基线上，可左键画点、右键擦除；“写入文字”暂存当前字模，窗口底部与参考版一致只显示“确定”，按“确定”一次提交，直接关闭窗口则放弃整窗字库草稿。也可选择系统字体，将输入字符生成 12 像素预览，核对后写入；参考按钮“替换全部字体”在当前已验证安全范围内只处理选中的一页和已有单字码表映射，遇缺字时整批拒绝。普通写入只改字形，不改变码表；同一码的所有名称/剧情都会受影响。

每页有 224 个独立字模。E/F 列实际引用同一行 0 列，不可独立写；每行四个保留字节不会被清页或批量导入覆盖。“清空本页”需确认；页点阵 `.dcfont` 固定 4032 字节，按行从 0 到 D 列排列，不含 E/F 别名和行保留字节。

右键单击左侧字模网格可使用增强操作：导入/导出本页点阵；“自动分配新字符…”；导入/导出 `.dcfontset` 全字库；“检测未使用文字…”；“清除未使用的自定义字模…”；“安全回收未使用内置文字…”；“恢复已回收的内置文字…”。初始自动分配只会选“码表未占用、该 Token 在基准 ROM 全文件从未出现、当前工作 ROM 也仍为零引用、18 字节字模为统一填充值”的槽。剧情/战斗通道可使用 B/C/D 十二页，推荐 ROM 初始 76 个安全槽，回收后 561 个；人物、机体、武器、道具和系统资料名称只使用 `C8—CB/D8—DB` 八页，初始 20 个安全槽，回收后 302 个。右键手工分配也默认使用名称兼容的 C/D 页。已有字符、安全槽耗尽、系统字体缺字都会拒绝。

现在不必先进入字库页手工分配：在剧情、战斗对白、胜利文字、系统/商店对白，以及人物、机体、武器、道具名称字段中输入码表没有的汉字，应用时会自动生成 12×12 字模、分配本通道的安全 Token，并与原字段写入合并为一次事务；一次撤销会同时撤回字段、字模和工程映射。编码前还会拒绝名称字段中的 B 页原始代码，避免“编辑器能解码、游戏名称渲染器却不能显示”。同一个新字如果先在剧情 B 页分配、后来又用于名称，工程会为名称补建 C/D 页兼容别名；两份字模和映射可随 `.dcmod`、`.dcfontset` 保留，各通道编码时自动选择正确别名。

推荐 ROM 的现有名称记录已按真实表逐项审计：机体 255 条、人物 199 条、武器 255 条、道具 24 条均只引用 C/D 页，未发现跨页违规，因此不会为了“整理”而无谓搬动现有文字。只有新增文字或跨通道复用时才按需建立兼容别名。

“检测未使用文字”会排除 12 页字模存储区后扫描整份 ROM，分别报告已引用字模、可安全回收的零引用内置文字、零引用自定义文字、已回收内置文字和“无映射但有图形”的旧字模。自定义清理会移除零引用工程映射并清空对应 18 字节字模；内置回收则在提交前再次扫描引用，把仍为零引用的内置代码从工程码表停用并清空字模，使代码进入自动分配池。两类操作都先进入窗口草稿，按“确定”才以一次可撤销事务提交。

“恢复已回收的内置文字”从打开工程时的不可变基准 ROM 恢复仍未重新分配的字模与内置映射；已经分配给新文字的代码不会被覆盖。安全判定固定以基准 ROM 的原有空槽为起点，避免清空点阵后字节模式变化产生新的误报。无映射但有图形的遗留字模仍只报告，因为缺少可证明的文字身份。回收状态和新映射均写入 `.dcmod` 工程；ROM 本身不保存 Unicode 名称，因此续改应打开 `.dcmod`。

`.dcfontset` v1 包含 12 页共 2688 个独立字模、48384 字节点阵和 UTF-8 自定义映射，导入会严格检查魔数、版本、长度、代码和值，并在完整校验后一次暂存；不包含 E/F 别名或 192 个行保留区。“写入文字”在点阵尚未变化时会保持灰色，这是避免无变化提交的状态，不是功能未开放；在 12×12 点阵中左键绘制或右键擦除后按钮立即启用。右键增强不增加参考版可见控件。2026-09-19 实际复核参考窗口未发现自动编码或文件导入/导出入口，因此该格式是新修改器的版本化产品协议，不宣称兼容未知的参考文件格式。可运行 `.\.venv\Scripts\python.exe tools\report_m11_font_compatibility.py` 复核，报告位于 `output/verification/m11-font-compatibility.json`。确定后仍需保存工程/派生 ROM；其他未核验 ROM 布局只读。

![地图动画](images/dc_modifier/05-map-animation.png)

**当前框体布局：**地图动画窗口现为 `900×650`；在 Windows 125% 缩放下实测物理高度约 812 px，与旧版截图的 818 px 接近，不再被 Qt 首次布局自动撑到屏幕可用高度。左侧“动画选择”与右侧“动画编辑”使用同级、顶端对齐的框体，宽度约为 `3∶7`；底部草稿状态位于低饱和信息框内。地图动画指令行高为 14 px，仍保持至少 23 行完整可见。

当前地图动画页保持 `900×650` 紧凑尺寸，左栏收窄，指令列表使用紧凑行高，一次可见至少 23 行。指令区使用旧修改器的白底/浅灰交替行和单一选中色。主列表严格采用旧版反汇编口径：隐藏 `F1` 刷新行；F9“创建物体”与紧随其后的 `40/42/C0/C2`“调取物体运行规律”是两条独立指令；坐标字节按旧版显示为 `000—255` 无符号十进制（例如 `$F8` 显示 `248`），不再转成 `-8`；图库、颜色、音乐、状态和规律代码保持两位大写十六进制，等待帧数、循环次数和屏幕有符号位移使用十进制。坠机爆炸因此显示“当前动画共 9 项动作”，真实 12 条底层指令只保留在悬浮说明和安全写入模型中。

地图动画主区按用户最终选择恢复为旧版式的“自然语言指令列表 + 底部代码编辑”结构：不显示表头、实时容量条、常驻结构按钮或内嵌参数网格，把高度完整留给动作列表；F9“创建物体”和 `40/42/C0/C2`“调取物体运行规律”各占一条真实指令和一行自然语言说明。双击某条实际指令可打开对应的颜色、声音、图库、物体或规律设置窗口；右键仍可插入、编辑、复制、粘贴、删除和清空。所有修改只更新本窗口草稿，点击整窗“确定”才写入工程/ROM，点“取消”全部放弃。F9 详情窗口显示物体编号与实际 X/Y 坐标；独立规律指令显示状态、取图和 X/Y 运行规律，其编号继续受真实表边界限制。

插入第一层恢复旧版窄栏和原顺序，如“F4定义声音、F0定义颜色、F3定义光束规律、F6写入IO端口2001”；第二层按指令显示“颜色设置、声音设置、物体设置”等专用分组，颜色窗口恢复三色并排、色块和“光束颜色/物理颜色”选择。尚未证明长度的 E2 仍按旧版列出但禁用，避免仅为外观一致而写坏 ROM。指令列表上方的内存进度条会按未保存草稿实时更新。左栏的主入口为“游戏内真实预览”：它将当前未保存草稿写入隔离测试 ROM，由随附 Mesen 运行游戏自身的地图动画解释器、PPU、调色板和场景数据，再播放逐帧抓取的真实游戏画面。`$00` 使用开始界面原生标题场景，其余动画在活动战场精神场景触发。播放器提供从头播放、播放/暂停、上一帧、下一帧、进度拖动和 0.5/1/2 倍速；预览只写入 `output/verification` 和 Mesen 测试存档，不覆盖当前 ROM/SRAM。“快速结构预览（非实机）”只用于即时检查组图、配色和等待结构，不作最终游戏效果依据。

地图动画 `$00` 已依据当前 ROM 脚本、资料中原 `$0C` 记录及调用位置命名为“开始界面标题组合动画”。它的等待、屏幕移动、循环次数和九色调色值均可通过专用参数框修改；九色指令使用 3×3 色块布局。该动画连续使用的 `F7 70 xx` 是固定三字节背景位置指令，只开放最后一个有符号 X 轴偏移，状态代码 `70`、操作码及循环地址继续锁定并由编辑器维护。

地图动画包含“地图动画、规律、动画调用”三个分类，直接读取当前 ROM。动画页已移除“原始字节”列，使用与旧修改器一致的单列自然语言描述；选中指令后可改参数，也可插入、编辑或删除完整指令。保存结构变化时不是只挪后一条记录，而是压实整个动画池：地图动画池共 7890 字节，推荐 ROM 的 60 条唯一脚本实际使用 5584 字节，原来分散的 2306 字节空洞都可重复利用；缩短任意脚本会立即增加剩余容量。重排会保持共享指针关系，并同步更新本脚本、其他脚本及跨记录的 `FE` 循环目标；删除仍被引用的目标、遇到无法证明的跳转或总量超过池尾时整项拒绝，不产生部分写入。“添加”仍会把当前动画复制到下一个 `$3F—$98` 预留槽，并把记录内循环地址重定位到副本。参考按钮“代码编辑”仍按旧版动线打开“请输入动画指针”对话框；确认当前表中的既有指针后定位对应记录。不存在的指针会明确拒绝且不修改 ROM；任意指针表改绑到未知地址的协议仍不开放。

规律页把“背景规律 / 运行规律 / 组图规律”恢复为协调的三列并排布局，便于同时核对名称、列表和内容。已确认解释方式的运行规律可改帧、位移、音效和循环次数。组图前两字节按当前 ROM 渲染例程确认为有符号 X/Y 起点，但参考 EXE 现场采集证明这两个界面值在“确定→保存”后不会写入 ROM，冷启动仍回到原值，因此新修改器只读展示 X/Y，不提供微调按钮。组图代码当前只开放已有保存/不同 PID 重开黄金的首图块字节 `$00—$EF`；后续拼图命令、运行时令牌与记录边界保持原值。背景规律的 106 个指针槽并非统一定长记录；现已按 ROM 内 `$D3E8` 取指、`$D3F7` 分发表和 `$D4FD—$D8D9` 处理器逐项分类：75 条能完整到达唯一结束边界，其中 69 条含可编辑参数，只允许修改 `$00—$ED` 绘制数据及 `$F8/$F9` 的两个固定参数。其余 6 条完整记录没有安全参数，31 条含动态地址、运行时长度、指针换页、提前结束尾部或缺失结束边界，保持只读。操作码、资源调用、变长/运行时参数、`FE` 布局头、`FF` 结束码和指针始终锁定；即使保持总长度，也不能把控制码当普通正文改写。地图动画和三类规律的名称框可编辑；名称保存在 `.dcmod` 工程元数据中，不修改 ROM 字节或全局默认配置，只打开派生 ROM 时需同时打开对应工程才能恢复自定义名称。运行规律“添加”只使用 `$7D—$9C` 的 32 字节 `FF` 尾池：当前地图动画必须恰好一次引用所选规律，且该位置的“组图帧序列/坐标位移”角色与源项一致；复制和把该唯一引用改到副本作为一个事务执行。首次最多复制 31 字节，未引用、多次引用、角色冲突或容量不足都会拒绝。组图规律“添加”只使用未被运行规律引用的 `$EB—$F6` 可调用尾槽，在 `$B338—$B38F` 的 88 字节尾池内从后向前分配，并把 `$F7/$F8` 保留为控制操作码；保留 5 字节空组图后，首次最多复制 83 字节。调用页用“精神：毅力”“地图武器：范围修理”等自然语言显示已知用途，技术地址和证据原因收进高级诊断。页面仍列出 86 个实际 `38 02 id` 位置，其中 78 个可更换已有动画编号，其余 8 个保持禁用和只读。

已核对的调用下拉框可在同一窗口内连续更换编号，也可改回打开窗口时的原编号；“确定”后保存派生 ROM 并重新打开应保留最后选择。地址/原编号或同址保存黄金以打开窗口时的 ROM 指令边界为准，后续每次仍检查当前调用指令和目标动画是否安全；这不会解禁其余 8 个只读调用。

为了让初学者能判断“为什么不能改”，背景选择后会直接显示可编辑参数数量，或动态地址、运行时长度、指针换页、尾部/结束码不完整等具体只读原因及相对偏移。调用表增加“状态/原因”列：78 个可写位置显示证据类型，8 个只读位置逐项显示编号冲突、地址偏差、仅有编号语义或嵌入数据未证等原因；禁用下拉框的提示使用同一说明，不再只显示笼统禁用。

背景/运行/组图规律仍按各自已验证参数门禁；非法动态代码会阻止确定并保留输入。地图及敌我动画主脚本允许完整指令级结构编辑，并自动维护已证明的 `FE` 控制流。共享记录的改动会影响全部引用者。地图动画窗口使用本地草稿，动画副本、代码、调用和工程名称在“确定”时合并为一次撤销事务，“取消”不修改工程。

武器动画插入目录中除“动画结束”外的 11 类参数窗口（F4、F0、F2、F3、E0、E1、FD、FE、F9、42/C2、等待）均遵守两级取消：参数窗口点“取消”只返回指令选择器，不插入指令；随后关闭选择器并在数据库点外层“取消”，不会改动动画池、指针、工程撤销栈或磁盘 ROM。该链路已在旧修改器隔离副本上逐项执行并以主窗口真实保存复核，11 类路径的保存前后 ROM 哈希一致；因此新版也以“参数窗草稿 → 武器页草稿 → 数据库事务”三级隔离实现，不能用关闭窗口后界面看似恢复代替零写入验证。选择“FF 动画结束”是旧版的直接动作，不再打开参数窗；鼠标左键和键盘聚焦后按空格都会执行，按钮右键则保持选择器原样且不写入。它会在所选行前结束当前逻辑武器的动画。若该脚本原本被多个武器共用，保存时按旧版创建当前武器的私有物理记录，其他武器继续指向原脚本，并同步搬移后续指针与 `FE` 循环目标；若原脚本本来独立，则只在所选指令位置插入一个 `FF` 并后移后续池，不复制整条记录。我方共享首行/中间行、我方独立首行、敌方共享首行、敌方独立末动作五类旧版整 ROM 黄金均已由新版逐字节匹配；在已有结束行或其后的空代码行再次选择 FF，旧版保存为零差分，新版同样不建立草稿。数据库撤销/重做也包含在回归中。

指令目录的按钮手势也按旧版分别处理，而不是只验证鼠标左键：F4 至等待的 11 项在按钮获得键盘焦点后按空格，会打开与左键相同的参数窗口；FF 按空格直接执行。12 项按钮的右键都不打开菜单、不关闭选择器且不建立草稿。上述 36 个“按钮×手势”组合已经在旧版隔离副本逐项实跑；参数窗全部取消、数据库外层取消后再调用主窗口保存，ROM 仍逐字节等于基准。

动画内容列表的旧版产品菜单共九项：插入、编辑、剪切、复制、复制全部、粘贴、粘贴全部、删除、清空。复制/粘贴以旧版的一条可见指令组为单位；普通粘贴会从当前所选位置开始替换，并一并移除该可见行后属于它的隐藏附属指令，不是插入。需要增加新指令时请使用“插入”。剪切等于先复制当前指令再删除；复制全部保存除结束符外的完整动画，粘贴全部替换目标动画；删除只移除当前非结束指令，清空只留下结束符。确定保存时按武器编号重建动画池并按完整脚本内容去重，所以修改共享动画只拆分当前武器，其他武器保持原内容；粘贴全部或清空得到重复脚本时自动复用地址。上述五类破坏性保存已逐项匹配旧版整 ROM 哈希；窗口会话内剪贴板、数据库草稿和外层取消仍保证磁盘 ROM 零差分。

### 3.5 计算器、存档与其他

![属性计算器](images/dc_modifier/07-attribute-calculator.png)

属性计算器已按参考窗口改为“敌方 / 我方”对称面板和逐行结果列表。人物下拉包含 001—200；机体下拉读取当前 ROM 的全部机体；武器下拉只显示当前机体实际装配的两个槽位，空槽显示“无”。当前推荐 ROM 会默认定位到人物 `$04`和第一台具有有效武器的机体 `$09`，装配武器为 `$07/$0B`。人物原码、精神、成长、补正与武器原码/特技/距离补正表改为下拉提示，不再挤占参考版面板。窗口采用1000逻辑像素默认宽度、940最小宽度，两侧第一列预留145像素，在完整显示常用武器名的同时避免横向拉伸过度。敌方使用低饱和暖灰、我方使用浅青灰、计算区使用中性冷白；字段标签改为透明底，分区更清楚且不形成大面积色块。

等级只允许 1—60，切换人物、机体或等级时，按固定成长值或 201—253 成长曲线累计，再加人物强度/防御/速度/HP 补正；三项战斗数值按游戏上限 255，HP 按 9999 截断。三地形火力与游戏及参考计算器使用同一“最终火力”口径：`floor(强度 × 强度系数 ÷ 强度除数) + ROM 武器地形火力 × 武器系数`，尚未扣除目标防御。默认人物/机体/武器组合因此显示 `floor(98×13÷10)+5×10=177`，不是此前误判的 58。如在“其他”窗口改了 M17 参数，下次计算会重新读取，不使用独立副本；手工改变强度时三地形最终火力也会同步刷新。

“开始计算”会分别输出我方和敌方的命中临界、最低命中速度、严格大于判定的双击边界、预计伤害、机体防御特技后实际伤害、剩余 HP 和击落次数。首次点击后开启实时联动：任一侧的人物、机体、武器、等级、属性、倍率、命中、射程、火力或特技变化，结果都会在同一事件循环自动重算，并把列表滚动到刚修改的敌方/我方段；打开窗口时仍保持结果区为空，避免尚未装配就显示无意义数据。每组结果的标题明确写成“阵营「人物／机体」使用「武器」→ 阵营「人物／机体」”，命中、双击、伤害和击落结论也重复主体，不再只显示脱离上下文的“可以命中”。命中使用当前武器距离补正表的最大射程列后与 M17 临界值比较；最低速度按 `ceil(临界值×100÷距离补正)+守方速度−武器命中` 求出实际最小整数，并直接显示“至少为 N”、目标速度、武器命中、临界和距离补正。旧修改器会在相同装配下给出负数估算，未按当前完整命中链路求精确边界，因此不作为新窗口的数值目标。伤害按目标机体的空/陆/海类型选用对应最终火力，再减 `floor(目标防御×防御系数÷防御除数)`；默认组合为 `177−42=135`。机体特技下拉只保留当前伤害计算实际处理的6项：无、T防御系统、相对转移装甲、VPS防御系统、重力波罩和用盾防御。先制攻击、反伤、一击脱离等不改变本计算器伤害的标志不进入下拉；机体原始组合值仍保留在提示中。选择后结果实时重算，但只影响当前计算器，不写入ROM。本窗口始终不写ROM，无确定/取消。参考版两个“更改倍数”按钮会触发运行时错误；新修改器不复刻崩溃，而是把它们实现为安全的分子/分母编辑框，范围均为1—99，只影响当前窗口本次计算。倍率也可直接按“分子/分母”格式输入。实现侧机器门禁见 `output/verification/m15-attribute-calculator.json`，完整现场步骤见 `docs/M15验收清单.md`；该增强不宣称参考版按钮已有正常黄金行为。

存档修改器不依赖当前 ROM：未载入 ROM 时，“数据”菜单仍显示且只有“存档修改器”可用。窗口只接受恰好 8192 字节的 FCEUX/Mesen 电池存档；“读取存档”会检查三个固定槽位（文件偏移 `$1C81/$1D7E/$1E7B`，每槽 `$FB` 字节）及各自 16 位小端累加校验和，并以 `N：第NN关 · X人` 或 `N：没有数据` 显示摘要。关卡原码为 0—31，界面显示 01—32。

上表共 11 列，读取所选有效槽的 16 格常驻队伍；所选槽无数据时，以活动记录 `$1411` 的常驻区作为新槽模板。人物、机体、等级、机动/强度/防御/速度/HP 附加值及 EXP 均来自已确认字段；载入 ROM 时显示人物/机体名称并把附加值换算为最终属性，未载入 ROM 时名称显示十六进制 ID、属性列显示原始附加值。下表同为 11 列，读取活动战场的 18 格敌方快照；人物、等级、机动、强度、防御、速度和当前 HP 对应已确认 SRAM 数组，可编辑。活动 SRAM 不保存逐敌机体 ID 和金钱，只有当前 ROM 的关卡部署可唯一匹配时才显示推导出的机体名称与基础金钱，这两列始终只读，不会伪造写入。

“写入存档”只改内存副本：把上表写入所选槽并重算校验和，把下表写回活动战场已确认数组；此时磁盘文件不变。“保存存档文件”才原子覆盖所选 `.sav`，覆盖前在同目录建立唯一时间戳 `.bak`。表格改后未先点击“写入存档”时禁止落盘；关闭含未保存内存改动的窗口会询问保存、放弃或取消。完整现场步骤见 `docs/M16验收清单.md`；实现侧协议报告为 `output/verification/m16-save-compatibility.json`，用户签收仍需单独填写。

旧版“其他”窗口已连接下列经反汇编与三份兼容 ROM 交叉核对的字段：3 项双击公式、5 项伤害公式、命中阈值、11 项道具效果，以及 6 组“人物 / 机体”初始阵容。当前界面会把数值嵌入完整的双击、伤害和命中公式中，并为 11 项道具效果及人物1/机体1至人物6/机体6逐项显示名称；道具名称以及“人物1：/机体1：”至“人物6：/机体6：”保留旧版末尾全角冒号，道具项按旧版四行三列顺序排列，避免只见数值、标签错位或遗漏标点，同时保持公式、道具和初始阵容三个区域清晰可辨。初始人物和机体下拉同样只显示 10 行；打开弹层的第一次按住移动与松开不会改动原配置，必须再次明确单击条目才会形成草稿。人物 `$1D/$1E` 的“？？？”是 ROM 正式名称，不属于缺字或空槽。打开窗口时读取当前 ROM，按“确定”把全部值作为一个撤销事务写入，按“取消”不产生修改。人物和机体下拉框保留 ID 0，以便无损打开特殊或占位记录。全部数值使用 0—255；伤害公式第 3、5 项是除数，不能为 0。经参考 EXE 的 20 项单变量保存与重开实验确认，双击公式每项实际有三份运行时操作数；修改器会同步写入全部三个镜像，避免不同战斗路径取到旧值。载入时和每次写入前都会校验公式/效果立即数周边的固定 opcode、存储目标、跳转或调用目标；立即数本身是通配位，因此合法改过数值的 ROM 仍能重开，但代码上下文已移动或损坏时会拒绝写入。M17 机器门禁 `output/verification/m17-global-compatibility.json` 会同时复验 38 个物理落点、32 个逻辑字段和 33 份参考黄金用例。

道具区的名称和值按旧版控件实际空间位置配对，而不是按控件编号大小猜测：从左到右、从上到下依次为超合金Z、磁性涂料、传感器、C装甲、超合金W、助推器、传感器2、M合金、电子盾、正义、医治；推荐 ROM 对应显示 `1,1,1 / 5,3,1 / 3,3,25 / 25,50`。窗口默认采用接近旧版比例的 `780×540` 逻辑像素；只保留公式、命中/道具和初始机体四个主要分区，不再给每个字段叠加独立边框。三个公式区使用无色块标题和左对齐公式行，避免内容悬在大面积空白中央；道具与初始阵容采用紧凑的“标签＋输入框”排列，底部状态改为单行提示，使信息密度和操作位置更接近参考窗口。

M08—M18 的汇总机器门禁见 `output/verification/m08-m18-delivery-gate.json`，实现状态、每个模块的验收入口和未关闭范围集中记录在 `docs/M08-M18验收汇总.md`。

系统文字和成长方式位于数据库“其他修改1”；道具名称、价格及说明位于“其他修改2”。商店店员与对话的具体支持范围见对应页面和差异矩阵。

## 4. “扩展功能”菜单：新能力

新功能没有挤占参考工具的“数据”菜单，统一放在“扩展功能”：

| 入口 | 用途 |
|---|---|
| 完整ROM数据读取 | 七类结构化全表、文件偏移、完整原码及逐字节 HEX（只读） |
| 战斗背景音乐 | 修改双方战斗曲，导入 `$9D–$9F` 扩展曲槽 |
| 机体导入与 CHR 图像 | 导入/导出 `.dcunit`，编辑已验证的活动 CHR 图块 |
| 扩展容量规划 | 自动给地图、机体和剧情分配 Bank 并接通运行时 |
| 工程概览 | 查看 Mapper、哈希和可用资源 |
| 变更与验证 | 查看字节改动并运行完整结构检查 |

**制作信息与出演名单：**该内容属于地图动画 `$13`“制作信息介绍与序幕”和 `$14`“序幕下移滚屏”的演出链。打开“数据 → 地图动画”，选择 `$13` 或 `$14`，再点击左侧“字幕内容（制作信息与出演名单）”。窗口左侧编辑、右侧即时预览，Enter 写入原 `F1` 分行码，普通空格写入原 `AF` 对齐码；两段同时显示字节、行数和单行显示格。制作信息限制为 75 字节、3 行、每行最多 18 格；出演名单限制为 109 字节、11 行、每行最多 10 格。较短内容用 `AF` 补齐，任一限制超出时禁用确定，因此不会移动后续数据或破坏原滚屏版面。字幕窗口“确定”只暂存到地图动画草稿；此时打开快速预览或游戏内真实预览，会使用已暂存的字幕和动画，但不提前改动工程。随后地图动画窗口“确定”才把动画、字幕、可能自动补入的字模和工程映射作为一个可撤销事务提交，地图动画窗口“取消”则统一放弃。

推荐 ROM 的“勒”位于出演名单第三段“盖塔　太勒”，代码 `C9F3`。若在本窗口删除或替换该字并确定，全 ROM 引用会由 1 降为 0，之后才会出现在字库的安全回收结果中；仅清空字模而不先移除正文引用会被保护规则阻止。

### 4.1 自动容量规划

![扩展容量规划](images/dc_modifier/10-resource-manager.png)

推荐基线共有 464 KiB 托管空间。第一次需要扩展内容时，从“扩展功能 → 扩展容量规划”选择地图、机体和剧情额度，再点击“自动分区并接通”。推荐值为：

| 类别 | 推荐 | 规则 |
|---|---:|---|
| 地图 | `304 KiB` | 8 KiB 递增，共享给地形、部署和触发点 |
| 机体 | `48 KiB` | 可选 48/64/80 KiB；普通编辑选 48 KiB |
| 剧情 | `112 KiB` | 每 16 KiB 对应一个可变长文本组 |

三类配额按完整 Bank 固定边界，分配器会登记占用并禁止相互覆盖。规划完成后不需要手工填写运行时指针。`$61–$63` 是扩展音乐，`$64` 是双音频桥，`$7E–$7F` 是固定程序 Bank，均不会交给普通资源分配。

### 4.2 机体包和 CHR

![机体导入](images/dc_modifier/13-unit-import.png)

`.dcunit` 当前携带 16 字节机体记录、名称引用和可选连续 CHR 图块。机体的两格独立武器表不在版本 1 包内，导入不会随包覆盖该表；导入前先核对目标 ID 和图块范围。目标当前若使用重复属性指针，导入时会自动拆分，数值与名称均只覆盖目标机体。

![CHR 图块编辑](images/dc_modifier/13b-chr-editor.png)

CHR 页提供真实 8×8 图块的放大绘制和 PNG/CHR 导入导出。NES 图块只有 0–3 四级像素索引，不自带颜色；批量导入前必须确认连续图块范围。

单块 CHR 画布属于窗口草稿：切换图块、切换图块页或按外层“确定”时会自动提交合法像素；像素值无效时阻止切换并保留原画布。CHR 和 `.dcunit` 导出会把当前合法画布直接叠加到导出内容，只在文件写入成功后提交草稿；取消文件选择或写入失败不会暗中改动 ROM。导入时会在确认后把已有合法画布作为可撤销基线保留。“取消”仍会回滚本次窗口事务。

### 4.3 战斗音乐

![战斗背景音乐](images/dc_modifier/14-music-editor.png)

选择器可分别设置主动攻击曲和被攻击曲。扩展曲槽固定为 `$9D`、`$9E`、`$9F`，每槽占一个 8 KiB Bank。导入后必须运行完整检查，并在 Mesen 中验证播放、音效和切回旧曲。

“分配战斗曲”只给人物选择已有曲目，不会导入歌曲。要替换歌曲文件，展开“替换扩展曲数据 / 导入自己的曲子”；它会影响所有使用该曲槽的人物。技术导入区默认折叠，双音频引擎和导入格式不变。

## 5. 工程、撤销、验证与输出

“文件”菜单保持参考工具的打开、保存、退出命令和分隔位置；“完整ROM数据读取”已移至“扩展功能”，不再插入参考“数据”菜单：

- `Ctrl+O` 打开基线 ROM。
- `Ctrl+S` 首次要求选择派生 ROM 文件名（D1 超集安全行为）；之后继续保存到该派生文件，不再选择文件名。覆盖派生文件前自动生成不重复的时间戳 `.bak`。
- `Ctrl+Alt+S` 在“工程”菜单中执行“ROM另存为”。

`.dcmod` 工程、IPS 和构建功能位于“工程”菜单：

1. 使用“工程另存为”建立 `.dcmod`，以后按 `Ctrl+Shift+S` 保存工程。
2. 按 `F7` 打开“变更与验证”，处理全部错误；合法地图草稿会先提交，无效草稿会阻止检查并保留表单。
3. 使用“导出IPS”或 `Ctrl+B` 一键构建 ROM、IPS、工程副本和 JSON 报告。
4. 使用 `tools/vendor/mesen-0.9.9/Mesen.exe` 进入实际关卡、剧情和战斗验证。FCEUX 2.6.6 不适合验证本 1 MiB PRG Mapper 194 ROM。

所有“另存为”和资源导出操作（工程、ROM、IPS、机体包、CHR、音乐 Bank、扩展资源及字库模板）的默认目录均为 `output/exports/`。即使当前打开的是 `references/` 下的旧兼容基线，生成文件也不会默认写回只读参考目录。

![变更与验证](images/dc_modifier/11-validation.png)

输出前会再次检查 iNES 头、受保护 Bank、分区边界、运行时入口、文本容量和事件长度。有错误时不会生成正式 ROM/IPS。`references/` 内的任何路径均为只读目标；“ROM另存为”仍要求不同于当前打开的路径。覆盖已有派生 ROM 时会先建立唯一时间戳 `.bak`，连续快速保存不会覆盖前一份备份。

按 `Ctrl+Alt+Z` 撤销、`Ctrl+Alt+Y` 重做。撤销当前合法地图草稿时，修改器会先把它作为一个事务提交并立即撤销；无效草稿会被保留并阻止撤销。存在任何地图草稿时，重做会被阻止，避免清空已有重做历史。`Ctrl+Z` 保留给参考工具的“文字转换”，因此不能再作为工程撤销快捷键。

## 6. 草稿、确定与取消

- **记录切换：**机体、人物、武器、文本、事件和 CHR 图块等页面在切换记录前自动提交合法草稿。剧情窗口切换关卡或外层总览时也遵循同一规则；非法草稿会把选中项恢复到原记录。
- **地图切换：**切换关卡或保存前自动提交合法地图草稿。
- **非法输入：**长度、容量、Token、坐标或必选项不合法时，切换和“确定”会被阻止，不会悄悄丢弃表单。
- **确定：**独立数据窗口会先提交各页尚未应用的合法草稿，再保留整个窗口会话。
- **取消：**无论页内是否点过“应用/暂存”，都恢复窗口打开前状态。
- **磁盘保存：**独立数据窗口的“确定”只改变内存；仍需保存 `.dcmod` 或按 `Ctrl+S` 输出派生 ROM，当前载入的基线不原地覆盖。

## 7. 常见问题

### 如何判断某个字段能否变长

修改器现在按资源池而不是按单条记录判断容量：已确认“指针表＋连续池”或“顺序记录池”的资源，会重排池内记录并同步指针；脚本还会同步已验证的内部跳转。可运行 `\.\.venv\Scripts\python.exe tools\report_legacy_memory_distribution.py`，从旧修改器保存前后 ROM 证据重新生成 `output/verification/legacy-memory-distribution.json` 和 `docs/research/legacy-modifier/旧修改器全模块内存分布.md`。报告里的写入区间只表示旧版实际改过哪些字节，不等于空闲空间；没有增长/缩短、别名和运行时证据的区域仍会保持固定长度或只读。

人物和武器名称按各自名称池的总容量判断，不要求每条名称与原槽等长；只有整个池的净增长超过已验证池尾时才拒绝。机体名称采用原生优先、独立池兜底的两级落盘，但容量门禁只有一套旧版口径：当前 255 个逻辑名称独立展开为 `1456 B`，加旧版净增长余量 `6701 B`，即显示 `1456/8157 B`；名称加长 1 B 后显示 `1457/8157 B`，剩余 `6700 B`。原生 693 B 物理区放不下时才分配 Bank pair，未修改不会预占扩展区。旧版 V5.1 的有效机体名称本来就是逐 ID 独立的；当前推荐 ROM 中 `$09/$0A` 的重复指针只是现有 ROM 布局，改 `$09` 时会自动拆分且不会连带改 `$0A`。总量超过 8157 B 时整次拒绝，不会覆盖武器名、初始配置正文或相邻未知数据。

数据库六个页签各自显示“本模块内存”，逐项列出 ROM 地址、固定结构/可重排池、共用对象、已用、容量、净增长余量和占用比例。固定结构显示“可改值”，含义是记录长度不能增加，但现有字段仍能正常编辑；“净增长 0 B”也不等于不可编辑。人物页摘要直接显示 Bank `$24` 的占用、共享余量以及“人物名称与属性已接通”，明细继续列出八类实际共用对象；“头像配置＋机体战斗外观共享尾区”按当前目录动态显示余量，头像拆分会在该复合区内重排。机体名称超出原生池后，机体页会明确显示“独立扩展池”；初始配置容量保持不变。某池的余量只能在已验证的共享关系内使用，固定区中的零字节、重复指针或旧工具差分间隙不算可用容量。

### 进入修改器后为什么是空白

这是未载入态：三页签空壳仍可见，但关卡列表为 `0 个地图`、编辑区禁用；“文件 → 打开”和 `Ctrl+O` 仍可用。选择兼容 ROM 后，标题追加 ROM 路径、关卡列表载入，地图和数据菜单才会启用。不会为方便操作而自动打开或改写推荐基线。

### 为什么图块是空位、地图没有地形

未载入 ROM 时没有 CHR 图块和地图记录可读；旧空界面出现的一格绿色和纯色方块是占位画面，不是游戏地图，现在不再显示。打开 ROM 后应出现实际图块与关卡地形。若标题已追加 ROM 路径、关卡数大于 0，但图块仍不正确，请提供该画面的截图、ROM SHA-256、所选关卡/图库和任何错误提示，以便按同一基线逐格核对；静态截图不能证明参考版与新修改器逐像素一致。

### 为什么一些看起来完整的按钮不能点

这些按钮按参考工具保留对应布局和入口，但其 ROM 地址或联动语义尚未完成差分验证。查看 tooltip 可以看到只读原因。真实预览不代表已允许写入。

### 点“确定”后原 ROM 为什么没有变化

“确定”只保留到内存会话。按 `Ctrl+S` 首次选择一个新 `.nes` 文件，之后继续保存到该派生文件；也可用工程菜单保存 `.dcmod`。当前载入的基线和 `references/` 下的 ROM 均不会原地覆盖。

### 文本或地图为何阻止切换

先阅读错误提示。常见原因是文本组超过 16 KiB、结束 Token 缺失、地图记录跨 Bank、部署坐标越界，或尚未进行扩展容量规划。

### 载入 ROM 或切换关卡为什么不再长时间卡住

当前版本只立即装载主地图页；机体、人物、武器、剧情、事件、容量等隐藏模块在第一次打开时才填充，之后复用页面内容。地图、初始配置和商店事件的全池容量统计会缓存未修改的编码正文，部署表也保留已创建的单元格控件，切换关卡不再反复扫描 100 张地图或销毁并重建整张表。任何工程写入、撤销或重做都会递增工程修订号并重建受影响 Codec，因此缓存不会掩盖新数据；首次打开大型事件页可能仍有一次性列表填充时间。

数据库和剧情编辑窗口现也按当前标签页延迟填充：打开窗口只准备首个可见页面，人物、武器、文本、商店、行动事件、劝降、地图事件及剧情文字在第一次切入对应标签时读取。已经打开过且工程数据未变化的数据库和剧情窗口会复用已解析页面；从其他模块修改 ROM 后则自动丢弃旧缓存并重建。其余工具窗口仍在关闭时销毁，以保证“取消”后的草稿不会在下次打开时复现，但共享的机体/人物/武器名称、剧情记录、CHR 图块、文字表和动画调用扫描会按工程修订号复用，写入、撤销、重做后自动失效。地图动画的 86 个动画选择框共享同一只读选项模型，不再各自复制 153 项；剧情总览和武器使用关系只在工程或当前记录变化时重算。

“完整 ROM 数据”窗口也采用逐页加载：打开时先显示轻量骨架，机体、人物、武器、地图、文字、动画、关卡事件和完整 HEX 只在第一次切入时解析，已加载页直接复用。大型表格初始保持 ROM 自然顺序，用户第一次点击列标题时才启用排序，避免仅为打开页面先做全表比较；机体页会一次读取全部外观表，文字页会复用已解析记录与共享项，不再逐行重复扫描相同指针池。

离屏/进程内计时只用于定位代码热点，不能当作用户从点击到完整画面出现的耗时。2026-09-28 使用正式单文件 EXE、Windows 原生输入和逐帧截图重新实测：冷启动到启动页约 `2.20 秒`，确认 ROM 到主地图完整绘制约 `2.34 秒`；地图动画首次完整出现约 `2.17 秒`、再次打开约 `1.17 秒`；剧情、字库、其他和文字转换首次分别约 `2.06/1.28/1.43/0.67 秒`。第一轮数据库测试在 `3.22 秒` 时仍出现白色内容区，完整内容约在 `3.2—3.8 秒` 内出现；进一步把五个隐藏标签的控件树改为首次访问才创建后，新正式版约 `2.75 秒` 已完整显示机体页，不再先显示白色内容区，再次打开约 `0.70 秒`。这些数值包含每次约 `0.5—0.7 秒` 的画面和可访问树采集开销，但仍比单纯构造函数计时更接近实际手感。原始离屏数据仅保留在 `output/build/profile-ui-all-modules-after.txt` 供开发诊断，现场数据和方法见 `output/build/profile-ui-actual-windows.md`；可按 `docs/性能与流畅度验收清单.md` 逐项复验。

### 输出 ROM 可以重新打开吗

可以。新 DC 扩容基线保存出的普通派生 ROM 即使没有自动容量规划表，只要固定代码认证、预留扩展区全零及完整性检查通过，也可用“文件 → 打开”或 `Ctrl+O` 在新会话中直接续改。带自动规划表的输出仍按规划布局与完整性检查重开；其他非基准哈希且无规划表的兼容 ROM、或预留区含未登记数据的 ROM 会被拒绝。普通派生 ROM 即使已经由地图页把事件表归一化到内置托管池，重开后也能继续执行首次自动容量规划；程序会先保留全部事件语义，再回收旧托管池安装扩展 Hook。若使用过高级资源分配，仍建议以原 `.dcmod` 续改，以保留资源 ID、名称和分配意图。旧版程序若弹出“只有带有效自动容量表的修改器输出 ROM 可以直接续改”，请换用本次更新的 EXE 重开；无需重复覆盖源 ROM。

### 运动规律模拟器的旧版操作顺序

运动规律模拟器是有状态的记录工具，不是单击一次即可播放的预览器。先点“开始”，在提示框点“确定”，再到黑色画布内左键创建物体；随后第二次点“开始”进入记录状态。“移动”会按当前 X/Y 产生两轴运动字节，界面采用十六进制显示，例如十进制 X=12、Y=13 显示为 `0C`、`0D`。“鼠标模拟运动”可勾选后用鼠标轨迹记录，完成后取消勾选并点“结束”。关闭该工具或取消数据库不会写入 ROM。

旧版真实状态链已在隔离 ROM 上自动复验：开始、创建物体、再次开始、移动、鼠标模拟开/关、结束和外层取消全部可达，最终 ROM 完整哈希不变。该验证只证明旧版行为基线和当前入口对照，不代表武器修改模块的全部递归动作已经闭合。

新版现按同一顺序工作：初始黑底红轴画布不预先放置物体；未开始时点“移动”会提示“请先点击开始”。旧版真实桌面输入证明，宽高、X/Y 和采样框不是只能使用微调箭头的窄范围：输入宽度 `0`、`101`、`-1`，以及 X=`-129`、Y=`128`、采样=`0`，失焦后都会原样保留；高度还实际保留了 `2147483648` 与 `-2147483649`，因此这里是自由十进制编辑框，并非有符号 32 位业务门禁。屏幕几何进一步确认旧版 Edit 150 是宽度、Edit 170 是高度，不能按控件树的邻接顺序反推标签。五组上下箭头均有独立的 `0—100` 循环范围：`37→38→37`、`100→0`、`0→100`；越界正值点上箭头归 `0`，越界负值点下箭头归 `100`。新版使用同样的双重语义，并保留 Ctrl+A/C/V 和标准编辑右键菜单。进入记录后一次“移动”分别写出 X=`7F`、Y=`80`，即轴值按低 8 位生成两位十六进制，采样 `0` 视为每次都记录；负宽高在画布上仍按旧版可观察结果至少画一个像素。鼠标模拟记录相邻鼠标位置的增量。“播放代码（增强）”保留此前的离线代码播放能力，但与旧版“开始”录制动作明确分开，不改变旧版动线。

画布手势也按状态解释：只有第一次“开始”并确认后的创建态，画布左键才建立物体；结束后的空闲态双击、右键和拖拽不会修改代码或坐标，也不会弹出功能菜单。递归功能前沿已把可见的运行时 `Afx` 画布 ID 100 单独登记为四类动作；宽度、高度、X/Y、采样五个编辑框及五组箭头也已逐控件取得旧版证据。X/Y 运行规律代码框和旧版一样允许先保留任意多行草稿，支持原生全选、删除及右键编辑菜单；只有点击预览或实际使用代码时才校验两位十六进制字节，不会在键入阶段擅自删除内容。隐藏的 `_EL_DrawPanel` ID 280 已确认只是不可达模板，不再重复计入分母。四个规律页的真实功能分母现已 `266/266` 闭合：20 个常规按钮及 5 个条件/边界按钮、外层确定/取消均分别实跑左键、右键和焦点空格键；其中运行规律的图块增加按钮会稳定复现旧版自身“数组成员引用下标超出定义范围”错误，作为参考行为保留。四个主列表的真实数量为 `255 / 252 / 250 / 255`，共 1012 项均逐项完成左键、双击、右键和键盘 Home/Down 遍历；16 个输入框、4 个微调器、2 个下拉框、页签键盘循环及 62 项条件显隐/启用状态也已逐项实跑，数据库取消后 ROM 零差分。报告器现同时规范化主窗口 ROM 路径，并只为曾经可见且启用的控件生成手势；永久隐藏或禁用的模板仍参与状态发现，但不再制造不可执行动作。Windows 自带 Edit 右键菜单按 83 个已观察入口统计，不把随语言包变化的 27 个 Unicode/输入法命令当成产品功能；输入框右键与快捷键仍逐控件验证，产品自定义菜单命令继续逐项保留。机体拼图 `73/73`、碎片拼图 `62/62` 的按钮三手势、输入框、下拉框、碎片列表与条件状态也已在旧修改器中实跑；武器规律内的光束拼图 `28/28`、物理拼图 `38/38` 同样覆盖按钮三手势、下拉框和物理图块列表。每个会改草稿的按钮都从重新打开的子窗口开始，数据库最终取消，隔离 ROM 前后零字节差异。当前全局真实分母为 `3809` 项、已验证 `590` 项、待验证 `3219` 项，因此这些窗口闭合不代表全修改器已完成。
