二、问题根因

本 ROM 使用 Mapper 194，并在战斗 IRQ 中启用 MMC3 CHR 反转模式。

我方紫色武器使用低 tile $06-$29，位于 sprite R0；战斗区和 UI 区的 R0 都是 $FC，
所以我方武器进入 UI 后仍能正常显示。

敌方紫色武器由动画对象把同一组低 tile 异或 $80，生成 tile $86-$A9，位于 sprite R1。
上半屏 R1=$FC，而 UI 区 R1=$12；因此同一个 $86-$A9 在 UI 中被解释成另一套字形，出现紫色方块和碎片。

本修复不隐藏武器、不扫描整张 OAM、不切换 UI CHR Bank。
只把敌方武器对象的异或掩码从 $80 改成 $F0，并把对应图案复制到上下两套 R1
共同未使用的 tile 槽：$D0-$D9、$E0-$EF、$F6-$FF。

三、6502 代码修改

1. 文件偏移 0x07D0F5，CPU $D0E5，4 字节

原代码：20 67 F4 EA
新代码：A9 04 85 15

原指令：
    JSR $F467
    NOP

新指令：
    LDA #$04
    STA $15

作用：保持原行为，释放固定 Bank 的 $F467 区域给新帮助例程。

2. 文件偏移 0x07D1E7，CPU $D1D7，5 字节

原代码：85 1E BD 30 07
新代码：20 67 F4 EA EA

原指令：
    STA $1E
    LDA $0730,X

新指令：
    JSR $F467
    NOP
    NOP

作用：在动画对象初始化阶段调用一次重映射判断；不是每个 OAM 子精灵调用。

3. 文件偏移 0x07F477，CPU $F467，19 字节

新代码：
    85 1E F0 0B BD 40 07 C9 C2 D0 04 A9 F0 85 1E BD 30 07 60

反汇编：
F467  STA $1E
F469  BEQ $F476
F46B  LDA $0740,X
F46E  CMP #$C2
F470  BNE $F476
F472  LDA #$F0
F474  STA $1E
F476  LDA $0730,X
F479  RTS

作用：仅动画对象标记为 $C2 且原本使用高 tile 页时，把异或掩码 $80 改为 $F0。
机体对象 $C1、人物头像、UI 光标及我方低 tile 武器均不修改。

四、CHR 图案数据修改

CHR 起始文件偏移：0x080010；每个 CHR Bank 为 0x400 字节，每 tile 为 16 字节。

源图案：Bank $FC 的 tile $86-$A9（Bank 内局部 tile $06-$29）。

新 tile 对应关系：
    $86-$8F -> $F6-$FF
    $90-$9F -> $E0-$EF
    $A0-$A9 -> $D0-$D9

等价公式：新 tile = 原 tile XOR $70。

复制到顶部 R1 的 Bank $FD：
    tile $D0-$D9：文件偏移 0x0BF510-0x0BF5AF
    tile $E0-$EF：文件偏移 0x0BF610-0x0BF70F
    tile $F6-$FF：文件偏移 0x0BF770-0x0BF80F

复制到 UI R1 的 Bank $13：
    tile $D0-$D9：文件偏移 0x084D10-0x084DAF
    tile $E0-$EF：文件偏移 0x084E10-0x084F0F
    tile $F6-$FF：文件偏移 0x084F70-0x08500F

源数据范围：Bank $FC 局部 tile $06-$29，文件偏移 0x0BF070-0x0BF2AF。

3. 敌方反击第 324-344 帧：原 ROM 的 UI 边界紫色乱码变为完整圆环/光球。
