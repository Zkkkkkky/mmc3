## 已实际覆盖

- 地图高度与宽度分别输入边界值 `1`、`32`，界面重排画布并同步显示 RLE 容量；该轮尺寸草稿随后放弃，没有写入 ROM。
- 右键画笔在坐标 `(8,17)` 改一格后，RLE 从 `324 / 324 B` 变成 `326 / 324 B`，界面明确显示“超出固定容量”，未应用该超限草稿；左键画笔恢复该格后回到 `324 / 324 B`。
- 左键在坐标 `(7,18)` 将一个独立图块改为草地图块，RLE 变为 `322 / 324 B`，应用后导出 `work_modified.nes`。
- 关闭修改器并启动全新进程，重新打开 `work_modified.nes`；地图 `$00` 显示 `322 / 324 B`、尺寸 `26 × 27`、状态“已载入 · 无未保存修改”，确认导出结果能够重新载入。
- 中键在坐标 `(13,5)` 吸取左键画笔，左侧画笔预览更新，地图字节状态不变。
- “编辑图块属性”窗口已展示图库 D 的颜色表 1、防御补正、海属性、空/陆/海移动补正、公用颜色表 2/3 只读说明，以及滚动后的 B—F 行；补充录屏另行展示图库 G 可编辑字段和图库 H“仅显示预览”的只读状态。
- 新修改器界面逐项修改并保存图库 A 的颜色表 1、防御、海属性、空中/陆地/海上移动补正，六个结果均相对同一 `before.nes` 只变化 1 字节；偏移和前后值见 `fields/field-diff-manifest.json`。
- 新修改器界面修改图库 B 颜色 1 时同时触发既有的“缺失水面海属性补写”：`B-color1-ui.nes` 实际变化 2 字节（请求颜色 `$27→$28`，自动修复位图 5 海标志 `$50→$D0`）。另保留 `B-color1.nes` 作为严格单字段编码样本。
- 图库 B—G 的严格最小样本由新修改器使用的 `MapTileAttributeCodec` 生成并立即反解校验；每个文件只变化对应记录首字节。生成记录见 `fields/generated-b-g.json`，可用 `tools/generate_m02_field_samples.py` 重建和审计。

## 签核边界

- A 的六类字段、B 的真实 UI 自动修复行为、B—G 的单字段编码区间以及 H/公用色表只读边界均已有可复核材料；这些材料完成 H-05 的实现侧证据审计。
